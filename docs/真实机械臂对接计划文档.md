## 1. 需求说明

本次工作的需求是：

1. 将当前 InternS2 手术导航项目与华沿 E05-Pro 真实机械臂对接。
2. 项目启动时可以通过命令行参数选择运行模式：
   - `simulation`：继续使用当前 SOFA 仿真机械臂，效果和现有项目一致；
   - `real`：连接现场真实机械臂，网页中仍显示 SOFA 机械臂画面，但模型姿态必须由真实机械臂的实际反馈驱动。
3. 真实机械臂当前是什么关节姿态，网页中的机械臂就显示什么姿态；不能使用目标命令、预测姿态或插值结果冒充真实状态。
4. 真实模式需要处理项目坐标系、SOFA 坐标系、华沿控制器 Base 坐标系、法兰坐标系和工具 TCP 坐标系之间的对应关系。
5. 当前项目运行在远端服务器，现场 Mac 通过网线连接控制器。因此采用以下通信链路：

```text
远端服务器
  → 发送经过校验的高层命令到 Mac
  → Mac 将命令转换成 HansRobot TCP 协议
  → 华沿控制器执行

华沿控制器
  → 通过 10004 DataSheet 返回实际关节和状态
  → Mac 解析并发送到远端服务器
  → 远端 SOFA 使用实际关节角更新机械臂模型
  → 网页显示实时数字孪生画面
```

6. Mac 必须实现为机器人边缘网关，不是透明 TCP 转发器。它负责协议解析、状态检查、单命令执行、超时、去重、失联处理和审计。
7. 真机模式默认只观察。只有完成坐标标定、安全门禁、假控制器测试和当次现场自检后，才允许显式开启真实运动。

新服务器迁移交接记录的 Bundle 根目录是 `/home/ubuntu/LSL/interns2-dev-bundle`，真正的 Git 仓库是其中的 `app/`。现已根据 Bundle 顶层的现行脚本，将 `app/scripts/services/` 中的启动、健康检查、状态和日志脚本改为从自身位置解析 `app/`，使用 Bundle 的 `runtime/`、`software/`，并将新日志写入 `app/logs/services/`。今后统一在 `app/` 内开发和启动；Bundle 顶层原脚本暂时保留供基线比较，不在本计划中删除。新入口已在服务器完成 simulation 启动冒烟检查，但这不等于 Step 0 的全部测试和现场资料均已验收。

下面是 **Step 3 实现并验收 CLI 后的目标命令**。当前 `app/scripts/services/start_all.sh` 仅支持无参数的 simulation 启动，遇到尚未实现的模式参数会拒绝，不会静默忽略。Step 3 后在 Git 仓库根目录执行：

```bash
cd /home/ubuntu/LSL/interns2-dev-bundle/app

# 默认行为；不传 --robot-mode 时也必须等价于 simulation
./scripts/services/start_all.sh --robot-mode simulation

# 真机状态读取和数字孪生，默认禁止运动
./scripts/services/start_all.sh \
  --robot-mode real \
  --real-config configs/robot-real.local.yaml

# 仅在本文规定的真机运动门禁全部通过后允许申请运动
./scripts/services/start_all.sh \
  --robot-mode real \
  --real-config configs/robot-real.local.yaml \
  --real-control enabled
```

其中 `--real-control enabled` 只是允许服务器提出运动申请，不能绕过 Mac 本地 `ARMED`、现场确认和每条命令的安全检查。

## 2. 最终交付结果

### 2.1 仿真模式

```text
启动 --robot-mode simulation
  → 使用当前 SimulationWorker 和 ContinuousTrajectoryController
  → 现有入点移动、相对移动、遥测、相机和 MJPEG 行为不变
  → 现有网页、语音、手势、planner preview 和测试不回归
```

### 2.2 真机只观察模式

```text
启动 --robot-mode real
  → Mac 连接真实控制器
  → 读取实际 J1～J6、TCP、FSM、错误和安全状态
  → 远端 SOFA 被动更新六个关节和连杆
  → 网页显示 REAL / OBSERVE ONLY、source age 和连接状态
  → 状态过期时画面冻结并显示 STALE
  → 所有真实运动请求被拒绝
```

### 2.3 真机受控运动模式

```text
启动 real + enabled
  → 现场人员在 Mac 本地短时 ARMED
  → 用户在网页确认结构化运动参数
  → 远端只发送高层命令信封
  → Mac 重新检查最新实际状态、坐标、TCP、限位和期限
  → Mac 串行发送 HansRobot WayPoint
  → 根据实际反馈判断开始、运动和完成
  → SOFA 始终由真实反馈驱动
```

首版只开放经过验收的低速、小步、离散运动。公网 Servo、自动穿刺、力控推进和任意 HansRobot 字符串透传不在本轮范围内。

### 2.4 实时性目标

- 控制器 `10004` DataSheet 周期：50 ms，即 20 Hz。
- Mac 到远端状态上传：最高 20 Hz，队列采用 latest-wins。
- 网页遥测和数字孪生：目标 10～20 Hz。
- 机械臂采样到网页显示：首轮工程目标 p95 小于 250 ms。
- 所有页面必须显示状态 age；超过门限时冻结，不能继续显示为“实时在线”。

这些是工程验收目标，不是安全等级或医疗定位精度声明。

## 3. 本文使用方式

本文是后续开发和真机联调的执行顺序，不再重复配套分析文档中的全部论证。每个 Step 都包含：

- 目标；
- 前置条件；
- 本 Step 允许的真机动作边界；
- 需要新增或修改的文件；
- 实现内容；
- 测试方法；
- 完成标准；
- 停止条件；
- 推荐 Git 提交。

执行规则：

1. 严格按 Step 顺序实施，不跨 Step 同时大改。
2. 每个 Step 使用独立 Git 提交；提交前运行该 Step 的测试。
3. 每个 Step 的完成标准必须全部满足，才能进入下一 Step。
4. 任何安全状态为 unknown、stale 或互相矛盾时，一律按不安全处理。
5. 实际接口、配置或厂家返回与文档不一致时，先更新分析文档和本文，再继续实现。
6. 每次现场联调保存到 `artifacts/real_robot_commissioning/<日期>/<step>/`；真实配置、证书和未脱敏日志不得提交 Git。
7. 每完成一个 Step，在本节总清单中勾选；关键 commit、配置哈希和测试结论写在本文对应 Step。项目由一人开发，不设审批表、签字或见证人；真机动作前的现场安全检查仍必须执行。
8. `configs/simulation.yaml` 与真机配置严格分离；不能用真机参数覆盖仿真基线。
9. 本文中的速度、超时和误差目标需要通过现场测量确认；未经测量不得随意放宽。
10. 新服务器上的源码、测试、Git 操作与服务启动均在 Bundle 的 `app/` 内进行，统一使用仓库内 `scripts/services/`；portable 环境和 SOFA 仍分别位于 Bundle 的 `runtime/envs/`、`software/`，新日志位于 `app/logs/services/`。Bundle 顶层原脚本及旧日志仅保留供迁移基线对照。
11. 本文其余 Step 中的 `python3 -m pytest` 表示测试意图，不是让新服务器直接使用 PATH 中的 Python：实际执行时，agent/web 使用 `runtime/envs/agent-web`，planner 使用 `runtime/envs/planner`，SOFA 使用 `runtime/envs/simulation`；Mac 网关测试另用隔离的 Mac 环境。先核验对应解释器、依赖和 SOFA/Xvfb 环境，不得因缺少 pytest 就重建或覆盖 portable 环境。

### 3.1 四个总门禁

Gate A——允许连接真机只读：

- 协议 parser、fake controller、Mac 网关和远端会话测试完成；
- 真实运动路径在代码层不可达；
- 厂家版本兼容性和只读命令列表已经确认。

Gate B——真机只读链路验收：

- 型号、DeviceSN、PackageVersion、`IsSimulation == 0` 均已核对；
- `10003` 只读探针通过，`10004` 持续推流至少 3 分钟；
- 状态、错误、安全回路和实际关节与厂家页面一致；
- 断网或重启后只恢复只观察，不重放命令。

Gate C——允许申请首次运动：

- 关节映射、Base→SOFA、法兰/TCP、负载、安装角和工作空间已标定；
- 控制器与项目的安全限制均已核对并固定；
- 命令状态机和全部故障路径已在 fake controller 上通过；
- 响应、运动启动、运动完成、停止送达、停止确认五类有限 deadline 均已设置；
- 位置/姿态公差、稳定样本数和 dwell 均已设置，不存在阻断运动的 `null`；
- 厂家关键问题已有可追溯答复。

Gate D——每一条真机运动的现场门禁：

- 空旷台架、无患者，机器人可达工作区内无人，使用无工具或批准的钝性工具；
- 现场操作者位于工作区外且可立即触达物理急停；物理急停和安全回路已在当日按厂家流程于静止状态完成功能检查并留档；
- 机器人处于批准的 AutoMode/3PE/缩减模式，非自由驱动、非力控；
- DataSheet 和 command socket 均 fresh，FSM READY、无控制器/轴/急停/光幕/回路错误；
- TCP/UCS/负载/安装角读回一致；
- 实际起点、完整目标和整条路径满足关节限位、工作空间、奇异点及速度/加速度限制；
- 没有其他网页、示教器或脚本发送运动；
- Mac 本地 single-use `ARMED` 已绑定本次测试编号、命令指纹和依据状态，并且本次命令已经单独确认。

这里是总览；实际执行时，Step 10 的 15.6 运动预检与 Step 11 的 16.5 当次检查都是强制门禁，不能只按本段简表执行。

任一 Gate 未通过时，不得通过“先试一下”进入下一阶段。

### 3.2 三条硬停止线

1. Step 0～10：项目代码不得向真实控制器发送任何改变状态的命令。现场若需改变姿态或执行厂家标定，只能由现场人员按厂家流程操作，项目网关保持只读。
2. Step 11 之前：`real_robot.allowed_control` 必须保持 `observe-only`。
3. Step 12 之前：真实运动只能走 Mac 本地专用 commissioning 入口，不能由 InternS2、普通网页、语音或手势触发。

物理急停始终优先。`GrpStop` 在本文中只称为“普通 TCP 软件停止请求（非安全功能）”，不能称为物理急停或安全保护停止。

随后在新服务器核对模型完整性、CUDA 12.8 `nvcc`、GPU 占用和 inference 的 FlashAttention runtime patch，并确认原 Bundle 顶层服务没有占用 23333/8000/8001/8002 端口；再从 **Git 仓库 `app/`** 启动当前 simulation 四服务。仓库脚本会按 Bundle 相对布局选用 CUDA 12.8，设置迁移交接中的 NCCL 默认值，并默认使用 GPU 0～3 / TP=4；允许通过环境变量显式覆盖。已验证的现场基线实际使用 GPU 4～7 / TP=4，应记录真实值：

```bash

INFERENCE_TP=4 \
./scripts/services/start_all.sh
```

### 15.5 网关状态机

```text
DISCONNECTED
  → CONNECTED_OBSERVE_ONLY
  → NOT_READY
  → READY
  → ARMED
  → COMMAND_SENT  (potentially_moving=true)
  → MOVING        (potentially_moving=true)
  → STOPPING      (potentially_moving=true，直到确认终态)
  → READY         (potentially_moving=false)

任意状态 → PHYSICAL_ESTOP / SAFEGUARD / FAULT / STATE_STALE
故障恢复 → CONNECTED_OBSERVE_ONLY
```

`potentially_moving` 是与 UI/FSM 状态正交的持久锁存标志，不只是一个瞬时状态。命令可能已到达控制器但尚未出现 `moving=1`、响应丢失、进入 STOPPING、STATE_STALE 或 FAULT 时，它仍保持 true，不能因普通状态跳转或异常退出而清除。

发送第一个运动字节之前，网关必须把 command ID、指纹、依据状态、编码后命令摘要和 `potentially_moving=true` 写入 write-ahead command journal 并 `fsync`。只有取得可审计的未发送证据或真实终态证据后才能清除该锁存。gateway 重启后先以 observe-only 连接并执行只读 reconcile；如果不能证明上一条命令未发送或已经终止，则保持 unknown、禁止新运动并要求现场确认。重启本身不是停止措施。

`ARMED` 必须由 Mac 本地终端或仅绑定 `127.0.0.1` 的本地界面设置：

- 远端服务器不能单方面设置；
- 具有短 TTL；
- 只能在 Mac 已显示精确 proposal 后设置，并绑定 `test_id + command fingerprint + proposal session/source sequence + safety-state hash + expected actual start`；
- single-use；目标、限制、proposal/session、安全关键状态或起点漂移超限，以及动作被接受/拒绝/取消后均立即失效；20 Hz 新样本序号自然递增本身不导致失效，但最新样本必须同 session、更新不倒退、fresh，且安全字段与起点仍满足绑定条件；
- 断线、stale、错误、停止或重启后立即失效；
- 不能自动重新武装。

### 15.8 命令生命周期和停止

命令状态：

```text
created → accepted → executing → succeeded
                     ↘ failed / unknown / cancelled
```

判定规则：

- `WayPoint,OK` 只产生 accepted；
- 发送第一个运动字节前，write-ahead journal 已持久化并确认成功；
- 在 `motion_start_timeout_ms` 内观察到运动，并用 `ReadCurWayPointID` 核对本次 ID；
- 从发送第一个运动字节前到确认终态一直保持 `potentially_moving=true`；
- 在 `motion_completion_timeout_ms` 内回到 READY、非 moving、`InPos=1`；
- 实际位置和姿态连续达到配置样本数及 dwell 后才 succeeded；
- 响应丢失、无法确认执行结果时进入 unknown，不自动重发；
- 未开始、永不到位和所有等待都有有限 deadline，不能无限轮询。

普通 TCP 软件停止请求：

- 可清除尚未发送的普通命令，但不能越过同一 `10003` socket 上已 in-flight 的请求；
- 仅当 gateway 自己拥有 active command 或其持久 journal 显示 `potentially_moving=true` 时开放；纯 observe-only 阶段不能由远端借此干预厂家页面、示教器或其他写入者的运动；
- 针对上述自有命令，停止请求豁免 ARMED、运动租约、普通运动 preflight 和人工确认；
- 仍需认证、限流、command ID 幂等和审计；
- 分别记录 `delivery=sent|not_sent|unknown` 与 `motion_stop=confirmed|unconfirmed`；
- 超过送达或确认 deadline 时提示现场使用物理急停，不能显示“已停止”；
- 未经厂家确认，不自行增加第二条写连接。

统一 watchdog 规则：DataSheet stale、操作者会话或匹配租约丢失、server/WAN 断开、command socket 异常、任一安全状态变坏或收到 shutdown 请求时，立即禁止新命令、清除尚未发送队列并撤销 ARM/lease。若持久锁存显示 `potentially_moving=true`，且 gateway 进程仍存活、command socket 可用，Mac 在本地尝试普通 TCP 软件停止请求并等待有限的送达/确认 deadline；未送达或未确认时记录 `unconfirmed`，明确要求现场使用物理急停。若 gateway 崩溃、Mac 睡眠/失电或 command socket 已断，软件无法自行发送停止，只能依赖现场物理急停和控制器硬件安全行为，不能把 supervisor 拉起进程当成已经停止。

外部写入检测：

- 当前 WayPoint ID 不是本地 active ID；
- 无本地命令却出现超噪声阈值的姿态变化；
- FSM 或程序状态发生非预期变化。

发现后立即撤销 ARMED；若自有 command journal 同时处于 potentially-moving，则请求停止并要求现场核查。

- 代码 commit、配置哈希、机器人 DeviceSN 和测试编号；
- 当前关节、Base TCP、TCP/UCS、负载和安装角；
- FSM READY、上电、使能、抱闸和 fresh age；
- 无控制器/轴错误；
- 急停/光幕及两路回路均正常；
- 现场核对的 AutoMode、3PE 和缩减模式；
- 自由驱动、力控均关闭；
- 当前姿态远离关节限位、奇异点和障碍物；
- 命令方向、距离、速度、零旋转、半径 0；
- 没有其他 active command 或写入者；
- local-only commissioning lease 有效，且不存在远端 lease；
- Mac 本地 ARM 的 `test_id`、命令指纹、proposal session/source sequence、安全状态哈希和实际起点均与当前 proposal 绑定；最新样本仍 fresh、同 session、安全字段不变且起点漂移未超限。

### 16.6 首次运动顺序

1. 只观察 2 分钟，确认状态稳定。
2. 为 Base `+X 1 mm` 生成 proposal；Mac 显示完整起点、目标、限制和指纹，现场操作者核对后为这一条 proposal 设置 single-use ARM，再确认发送；速度不高于预先固定的 2～5 mm/s。
3. 保存实际起终点、WayPoint ID、视频和外部测量，撤销 ARM。
4. 确认结果正确后，分别执行 `-X/+Y/-Y/+Z/-Z 1 mm`；每次都重新生成 proposal、核对指纹、设置 single-use ARM 和确认。
5. 六个方向全部重复通过后，另行现场自检并确认是否提升为 5 mm。
6. 软件停止真机试验另行现场自检：六方向验证通过后，选用低速、边界内且持续时间足以安全观察的相对轨迹，现场人员始终能立即触达物理急停；记录停止请求、送达状态、实际停止确认和最坏时延。若无法设计安全试验，不得为了勾选而制造运动，应保留“真机未验证”并不通过依赖该项的发布门禁。

本 Step 不执行任意绝对位姿。任何新的方向、距离、绝对目标或路径类型都必须先补充 fake 测试，再按本 Step 相同的 local-only commissioning 门禁单独验收。

每个动作完成必须同时满足：

- 本次 WayPoint ID 正确；
- 在启动 deadline 内观察到运动；
- 运动期间无错误和安全状态变化；
- 在完成 deadline 内回到 READY、非 moving、InPos；
- 实际 TCP 连续满足位置/姿态公差和 dwell；
- SOFA 显示和真实机械臂方向一致。

### 16.7 立即终止条件

- 任一方向与预期不一致；
- TCP、UCS、负载、安装角或模式发生变化；
- 真实关节/TCP 与 SOFA 超过阈值；
- 异常声音、振动、线缆牵拉、接近限位或非预期轨迹；
- 状态 stale、响应 unknown、deadline 超时或外部写入迹象；
- 任何错误、急停、光幕或回路故障；
- 现场任何人喊停。

终止后回到 observe-only。不得立即重试原命令，先确认机械臂实际停止并记录根因。

### 16.8 完成标准

- 六方向 1 mm 小步的真实方向、距离和 SOFA 显示均正确；
- 单独确认的 5 mm 测试通过，或明确记录为后续条件项；
- 响应、启动、完成、停止送达和停止确认最坏时延已经量化；
- 任何 deadline 到期都不会无限等待或显示假成功；
- 重复 command ID 不会产生第二次运动；
- 全部动作有原始遥测、日志、视频、外部测量和操作者确认；
- cloud handler 在 local-only 下不可达；
- 测试结束或重启后权限恢复为 observe-only，本地单次 ARM 不可复用。

### 16.9 停止条件

- 任一次运动方向、距离或姿态异常；
- 软件停止请求无法送达/确认且物理急停流程未准备好；
- 外部写入无法排除；
- 日志无法关联 server ID、WayPoint ID 和实际状态；
- 现场安全条件发生变化。

### 17.5 实现内容

控制路径：

- `RobotRuntimeHTTPController` 根据 runtime health 使用已选择的 provider；
- server 只发送版本化高层命令，不生成厂家 ASCII；
- command envelope 包含 session、command ID、创建/过期时间、依据状态序号、预期起点、TCP/UCS、目标、限制和确认 ID；
- Mac 使用最新实际状态重新计算相对目标并重复全部预检；
- 相同 ID/相同指纹返回缓存结果，相同 ID/不同指纹拒绝；
- 断线和 unknown 不重放。

每条动作必须走以下不可跳步的授权顺序：

1. 远端基于一个明确的 source sequence 生成不可执行 proposal；
2. Mac 重新计算并在本地显示完整起点、目标、frame、路径、限制、test ID 和 command fingerprint；
3. 现场人员只为该 `test_id + fingerprint + proposal session/source sequence + safety-state hash + expected actual start` 设置 single-use ARM；
4. 远端网页显示同一指纹并完成最终确认；
5. Mac 再执行 15.6 的全部预检，完全一致才发送；
6. 目标、限制、指纹、session、安全状态哈希、实际起点漂移超限或 lease owner 任一变化即使 ARM 失效，必须重新 proposal，不能静默刷新；同 session 的新遥测序号自然递增可以接受，但不得倒退、过期或改变已确认目标。

网页：

- 顶部持续显示 `SIMULATION`、`REAL / OBSERVE ONLY`、`REAL / ARMED`、`MOVING` 或 `STALE`；
- 真机确认框显示实际起点、完整目标、frame、TCP/UCS、速度、加速度、步长、配置哈希和 source age；
- 每条真机动作需要比仿真更严格的二次确认；
- 远端不能设置本地 ARMED；
- 状态 stale 时禁用运动按钮并冻结画面；
- 真机不提供“一键复位物理急停”。

停止和多模态：

- 真机红色按钮文案为“请求软件停止（普通 TCP，非安全功能）”；
- 真机语音/手势中的“急停”短语生成 `SOFTWARE_STOP_REQUEST`，不能伪造 physical estop；
- `SOFTWARE_STOP_REQUEST` 只有在 gateway 自有命令 active 或持久 journal 为 potentially-moving 时，才可豁免 ARM、运动租约和二次确认；仍要认证、限流、幂等和审计；
- 纯 observe-only 或只检测到厂家页面/示教器运动时，远端软件停止请求不得发送到控制器，应提示现场使用厂家控制和物理急停流程；
- 普通方向语音/手势只能生成候选 proposal，必须在网页显示完整数值并走本地绑定 ARM 与最终确认，不能直接执行；
- 仿真模式继续保留现有锁存 estop/reset 行为。

运动开放顺序：

1. 先用 fake controller 跑通网页完整链路；
2. 再用真机只观察运行；
3. 通过网页生成一条已经在 Step 11 验证的 1 mm 相对移动 proposal；Mac 显示并核对同一指纹后，现场人员设置绑定该 proposal 的 single-use ARM，再由网页最终确认；
4. 重复验证后再开放其他已批准方向和距离；
5. 真实 `move_to_entry` 在本 Step 始终返回 `OPERATION_NOT_ENABLED`，不影响真实相对移动和数字孪生验收；
6. 将来若要开放 `move_to_entry` 或其他新路径类型，先补齐完整 `Pose6D`、进近姿态、路径采样、TCP/工作空间核对和 fake 故障测试，再按 Step 11 同级的 local-only commissioning + Gate D 验收，最后才可申请远端开放。

planner 行为保持不变：只返回不可执行预览，`PUNCTURE_EXECUTION_ENABLED=false`。

### 18.5 故障注入

以下项目全部属于 **fake 必测**，由 fake controller 和隔离网络环境覆盖：

- `10003` 与 `10004` 分别断线；
- 半包、粘包、超长帧、坏 JSON、重复帧和时间倒退；
- WAN 丢包、延迟、断线和重连；
- Mac 睡眠、进程崩溃、网络切换；
- server、gateway 和控制器重启；
- 急停、光幕、回路故障、掉使能、掉电和轴错误；
- AutoMode/3PE/缩减模式变化；
- 自由驱动或力控意外开启；
- TCP/UCS、负载、安装角和配置哈希漂移；
- `OK` 后不运动、运动不结束、响应丢失；
- stop 无法送达或无法确认；
- 厂家页面/示教器造成外部 WayPoint ID 或未知姿态变化。

**真机静止 observe-only 可测** 的范围仅包括：在已确认机械臂静止、项目没有 active/potentially-moving 命令时，按预先核对的脚本验证 `10004` 停流、WAN 断开、server/gateway 受控重启、状态 stale 展示和 observe-only 恢复。物理急停/安全回路只按厂家规定在静止状态做功能检查；不得借故障注入规避厂家流程。

**真机运动默认禁止** 的项目包括但不限于：主动断 `10003/10004`、杀 gateway、让 Mac 睡眠/失电、拔网线、掉电/掉使能、触发急停/光幕、改变模式/TCP/UCS/负载或制造响应丢失。只有厂家提供书面试验流程、单项风险评审通过、现场安全负责人逐项批准且具备独立硬安全措施时，才可另立测试方案；本计划的验收不要求在运动真机上制造这些故障。

所有故障后都必须：

- 禁止新运动；
- 撤销 ARMED；
- potentially moving 时尝试发送普通 TCP 软件停止请求；
- 无法确认停止时明确提示物理急停；
- 重连后只回 observe-only；
- 不自动续跑或重放。

其中“尝试发送普通 TCP 软件停止请求”只在 gateway 进程仍存活且 command socket 可用时成立。gateway 崩溃、Mac 睡眠/失电或 command socket 已断时，系统只能把停止标为 `unconfirmed`，依赖现场物理急停与控制器硬件安全行为；supervisor 重启不是停止措施。

- Mac 双网络配置和 SSH/WSS 建链；
- 仓库内 health/status/logs 与 `app/logs/services/` 日志解释，并说明 Bundle 顶层旧日志不会自动迁移；
- 配置、证书和标定记录位置；
- 正常停机顺序：先撤销租约，potentially moving 时确认停止，再关闭服务；
- command socket 不可用时不能把杀进程当成停止机器人；
- gateway 崩溃、Mac 睡眠/失电或 command socket 断开时，软件无法保证发出 stop，必须执行现场物理急停/控制器硬安全流程并把停止记为未确认；
- 故障后先确认实际停止，再读取完整状态；
- 恢复必须回 observe-only，重新预检和本地 ARM；
- 何时必须联系厂家而不是自动复位。

### 18.8 最终完成标准

只有以下全部满足，才能声明“台架真实机械臂基础对接完成”：

- simulation 默认行为和现有测试无回归；
- CLI、日志、health 和网页不会混淆 simulation/real；
- Mac 通过认证的主动出站链路连接远端，机器人端口未暴露公网；
- 真实状态、六轴、TCP、FSM、错误和安全回路稳定可读；
- SOFA 只由实际关节反馈驱动，stale 时正确冻结；
- 关节、坐标、TCP、负载和安装角标定有记录并通过阈值；
- 真机运动经过配置、Mac 本地 ARM、远端确认和每条命令预检；
- accepted、executing、completed、failed 和 unknown 可以准确区分；
- 所有响应、启动、运动和停止等待都有有限 deadline；
- 普通 TCP 软件停止请求、物理急停和复位语义准确；
- 外部写入迹象能撤销 ARM 并失败关闭；
- 断线、重启和重复请求不会自动产生运动；
- 只读长稳、低速重复运动和批准的故障注入已经归档；
- planner 仍只返回不可执行预览，真实穿刺和 Servo 未开放。

### 18.9 停止条件

- 任一故障可导致自动恢复运动或命令重放；
- 审计记录不能重建一次真实动作；
- 长稳出现未解释状态跳变、内存持续增长或 source age 超标；
- 仿真模式发生回归；
- 现场要求扩大到临床、穿刺或安全功能，却没有重新开展独立风险评审。

```text
test: complete dual-mode real robot acceptance
```

## 20. 开发过程中禁止的捷径

1. 禁止让浏览器、InternS2 或远端服务器直接透传任意 HansRobot ASCII。
2. 禁止将控制器 `10003` 暴露到公网。
3. 禁止在未完成 Gate C 前把真机配置改成 enabled。
4. 禁止把 `WayPoint,OK` 当作运动完成。
5. 禁止响应丢失或重连后自动重发运动。
6. 禁止用命令目标、SOFA FK 或视觉插值覆盖真实反馈。
7. 禁止把仿真的临时 150 mm TCP 用于真实运动。
8. 禁止只校验终点而不检查直线路径、关节限位和奇异点。
9. 禁止把 `GrpStop` 称为物理急停或安全保护停止。
10. 禁止远程复位物理急停或远程设置本地 ARMED。
11. 禁止在 gateway 控制期间让厂家页面、示教器或脚本并发发送运动。
12. 禁止跨公网运行 Servo 点流。
13. 禁止自动上电、自动使能、自动循环复位和自动续跑。
14. 禁止让未知、stale 或互相矛盾的状态通过运动门禁。
15. 禁止因为 real 模式可启动，就认为已经允许真实运动。
16. 禁止把“台架基础对接完成”描述为临床可用或真实穿刺完成。

## 21. 每次现场联调必须保存的证据

- 测试编号、日期、地点和 Step；
- 代码 commit、运行环境版本、文档和配置 SHA-256；
- 机器人型号、DeviceSN、控制器 PackageVersion 和 gateway 版本；
- 现场操作者；如另有人负责 Mac 命令或物理急停，也记录其职责；
- 工具安装状态、TCP/UCS、负载/重心、安装角和安全配置；
- AutoMode、3PE、缩减模式、速度、加速度、步长和全部 deadline；
- 物理急停、光幕和测试区域检查结果；
- 每条 command UUID、WayPoint ID、确认人和 ARM/租约时间；
- 控制授权来源/owner、权限模式变化和 single-use ARM 绑定信息；
- 目标位置/姿态、frame、单位、速度、半径和限制；
- 发送前完整 preflight snapshot 与判定，包括 source sequence、monotonic age、expected start pose、command envelope fingerprint；
- 实际编码后的厂家命令、原始/解析响应和 artifact manifest 校验和；敏感字段必须脱敏；
- Mac 与服务器各自 wall/monotonic 时间的对应关系，不跨机器相减 monotonic 值；
- 发送、OK、开始、停止和完成时间；
- 起止实际关节、TCP、FSM、InPos、错误码和最终误差；
- `10004` 原始遥测、source age、丢帧、厂家页面截图和 SOFA 录像；
- 异常、软件停止的 `delivery=sent|not_sent|unknown`、`motion_stop=confirmed|unconfirmed`、是否使用物理急停、根因和恢复过程；
- 对应 Gate 的 pass/fail、现场确认人和未解决项。

# 新服务器统一启动命令

当前服务使用 Bundle 的 `runtime/envs/` 启动；仓库不再维护 Docker 镜像部署。旧文档中的 `docker build/run/compose` 命令仅作历史记录，不适用于新服务器。

在新服务器的 Git 仓库 `app/` 内完成开发和启动。仓库脚本会从自身位置定位 Bundle 的 portable 环境、SOFA、模型，并将日志写入仓库内的 `logs/services/`；默认选择 CUDA 12.8、交接记录中的 NCCL 参数、GPU 0～3 / TP=4。运行前应确认 Bundle 顶层原服务已停止，避免端口冲突。当前入口仅启动 **simulation**；真实模式参数将在真实机械臂计划 Step 3 实现后才可使用。

### 启动

```bash
cd /home/ubuntu/LSL/interns2-dev-bundle/app
./scripts/services/start_all.sh
```

如现场 GPU 分配有变化，可以在同一命令前显式传入已审批的 `INFERENCE_CUDA_VISIBLE_DEVICES` 和 `INFERENCE_TP`。不要为了启动而重新安装或覆盖 `runtime/envs/`，也不要删除 inference 环境中的 FlashAttention runtime patch。

保持启动终端打开；正常停止使用 `Ctrl+C`。新启动入口的日志写在 `app/logs/services/`；Bundle 顶层的旧日志不会自动迁移。

### 查看状态与日志（新服务器 `app/` 内）

```bash
./scripts/services/status.sh
./scripts/services/health_check.sh
./scripts/services/logs.sh all
```

单独查看可使用 `logs.sh inference`、`logs.sh simulation`、`logs.sh planner`、`logs.sh web` 或 `logs.sh xvfb`。

### Mac 本地访问网页

在 Mac 的另一个终端使用已配置的新服务器 SSH Host 别名（交接记录示例为 `interns2-robot-new`；如果你的实际别名是 `5090`，只替换最后一项）：

```bash
ssh -N \
  -o ExitOnForwardFailure=yes \
  -L 18000:127.0.0.1:8000 \
  interns2-robot-new
```

浏览器访问 `http://127.0.0.1:18000`。机械臂厂家页面 `192.168.0.10` 与此网页是两个不同入口。

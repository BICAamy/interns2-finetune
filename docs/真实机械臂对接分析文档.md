# InternS2 与华沿 E05-Pro 真实机械臂对接实施计划

> 文档状态：实施基线草案 v1.0
>
> 编制日期：2026-09-10
>
> 适用范围：研发台架、联调与数字孪生；不代表医疗器械验证，不允许直接用于患者或执行穿刺
>
> 核心原则：默认仿真、真机显式选择、真机默认只观察、任何异常失败关闭（fail closed）

## 1. 结论与关键决策

我理解本次目标包含两个彼此关联、但必须解耦实现的能力：

1. 项目启动时通过命令行明确选择 `simulation` 或 `real`。
2. `simulation` 模式保持当前行为不变。
3. `real` 模式下，远端网页继续显示 SOFA 中的 E05-Pro，但模型姿态由真实机械臂的实际关节反馈驱动，而不是由目标命令或预测值驱动。
4. `real` 模式最终允许经过确认的高层动作由远端服务器下发到 Mac，再由 Mac 使用华沿/HansRobot TCP 协议操作控制器。
5. 坐标系、关节方向、TCP、负载、安装角度和状态机没有验证通过前，只允许读取和镜像，禁止运动。

“远端服务器 → Mac → 机械臂”的总体方向合理，也是当前网络条件下推荐的方案。但要作如下关键修正：

- Mac 不是透明 TCP 代理，而是**机器人边缘网关**。它负责协议解析、单写者仲裁、状态门控、命令过期、去重、完成判定、失联保护和审计。
- 远端服务器只发送结构化的高层命令，例如“以 3 mm/s 移动到已验证的基座位姿”或“沿基座 X 轴移动 1 mm”。禁止从网页或模型输出中透传任意 HansRobot ASCII 字符串。
- 厂商资料没有定义 IF TCP 的 TLS、身份认证、请求序号或幂等机制，所以不能把 `10003` 通过端口映射、frp 或裸 TCP 隧道直接开放给远端服务。
- 机械臂的实时 Servo 点流不能跨公网传输。`StartServo`/`PushServoJ`/`PushServoP` 要求点在两个周期内持续送达，只能在 Mac 本地闭环，首版完全不启用。
- 真机状态优先通过控制器 `10004` 端口的 JSON DataSheet 以 50 ms 周期采集；控制命令通过 `10003` 串行发送；`10001` 只用于协议明确允许的快速读取命令。
- 远端真机模式仍启动 SOFA 服务。SOFA 在该模式下是**被动数字孪生渲染器**，不再自行推进机械臂运动。
- 当前项目的“紧急停止”语义必须拆分：网页经普通 TCP 能发出的 `GrpStop` 只是软件停止请求，不是经过安全认证的保护停止，更不是物理急停。现场物理急停按钮和安全回路永远是最终保护。
- `real` 模式启动不等于获得运动权限。真机默认进入 `observe_only`，运动还需要配置验收、现场操作者在场、本地控制租约和每次任务的人机确认。

在以下硬门禁全部通过前，本计划只推进到“真实状态读取 + 网页数字孪生”：

- 当前 `configs/simulation.yaml` 中针尖 TCP 仍为临时的 `[0, 0, 150] mm`，且明确标记 `provisional: true`、`real_robot_motion_allowed: false`。
- 当前 `MoveToEntryRequest` 只有目标位置和字符串形式的 `orientation_policy`，没有经过标定的完整目标姿态。真实针具运动不能仅凭 XYZ 下发。
- 当前 SOFA 正运动学来自官方 `485/elfin5` 模型并修改了力控法兰长度，但尚未用到场 E05-Pro 对 J1～J6 的顺序、正方向、零偏和笛卡尔位姿做真机交叉验证。
- 当前网页和编排器将软件 `estop` 当作可锁定、可远程复位的仿真状态；该语义不能直接复用到真机。

- `scripts/services/start_all.sh` 固定导出 `RUNTIME_MODE=simulation`，且固定启动 `robot-simulation:8001`。
- 当前网页不是浏览器本地 3D 引擎，而是显示远端 SOFA 生成的 MJPEG 画面。因此真机镜像应继续更新远端 SOFA 场景，而不是另写一套前端机器人模型。
- 当前仿真遥测已有 6 个关节角、TCP、轨迹、帧序号和时间戳，适合演进为通用 `RobotTelemetry`。
- `SurgicalTaskOrchestrator` 已有命令去重、单普通命令、停止优先、模式匹配、动作后位置复核等基础能力，但真机预检还缺少上电、使能、错误、光幕、控制器连接、FSM、数据新鲜度和本地租约等字段。
- 当前 SOFA 链路在 `ContinuousTrajectoryController` 内自己执行 IK 并推进关节；真机模式需要增加独立的外部关节状态入口，不能把真实反馈塞进仿真命令队列。
- 前端标题、接口路径、类型名和错误提示大量硬编码为“仿真”，真机模式需要泛化，同时保留旧接口兼容仿真。

厂商资料中的关键依据：

- 协议正文 1～3 页 / PDF 12～14 页：命令为 ASCII 文本，字段以英文逗号分隔，以 `,;` 结束；成功返回 `Command,OK,...,;`，失败返回 `Command,Fail,ErrorCode,ErrorExplanation,;`。运动命令返回成功只表示已受理，不表示已经运动完成。
- 协议正文 1 页 / PDF 12 页：控制器一次只处理一条完整消息；一次发送多条时只处理第一条，其余可能丢弃。因此命令连接必须严格保持一个 in-flight 请求，禁止 pipelining。
- 协议正文 4～7 页 / PDF 15～18 页：当前场景适合让控制器作为 TCP 服务端、Mac 作为客户端；普通命令端口为 `10003`，快速命令端口为 `10001`，JSON DataSheet 的 50/100/200 ms 端口为 `10004/10005/10006`。
- 协议正文 82～83 页 / PDF 93～94 页：`ReadRobotState` 返回运动、使能、错误、抱闸、暂停、急停、光幕、上电、电箱连接、路点融合完成和到位状态。
- 协议正文 86 页 / PDF 97 页：`ReadCurFSM` 返回当前控制器状态机。
- 协议正文 91～92 页 / PDF 102～103 页：`ReadActPos` 前 6 项是 J1～J6 实际关节角，随后是笛卡尔位姿、当前 TCP 和当前 UCS；XYZ 单位为 mm，关节角和 Rx/Ry/Rz 单位为度。
- 协议正文 181～183 页 / PDF 192～194 页：`WayPoint` 可显式指定 TCP、UCS、速度、加速度、过渡半径、运动类型和命令 ID，适合作为首版离散笛卡尔运动接口。
- 协议正文 257～263 页 / PDF 268～274 页：DataSheet 使用 4 字节 `LTBR` 魔数、4 字节总长度、4 字节 JSON 长度和 JSON payload；`10004` 推送周期为 50 ms。文档没有说明两个长度字段的字节序，必须在只读联调中抓包确认。
- 协议正文 264～265 页 / PDF 275～276 页：只有上一条运动完成后才可发下一条；`ReadRobotState` 的 moving 标志约有 50 ms 延迟，FSM 延迟更低。
- 错误码文档 44～46 页：状态 25 为运动中、27 为停止中、31 为零力示教、32 为暂停、33 为就绪；5 为急停、12 为安全光幕、17 为 EtherCAT 错误、20～22 为安全空间/碰撞/机器人错误。
- 软件手册正文 16～18 页 / PDF 24～26 页：坐标系选错可能造成非预期运动和碰撞；笛卡尔姿态按 XYZ 固定角表达。
- 软件手册正文 30 页起 / PDF 38 页起：TCP 是相对工具输出法兰的六维变换，必须针对安装后的真实针架标定。
- 软件手册正文 41 页 / PDF 49 页：机座安装角度必须与实际安装方式一致。
- 软件手册正文 47 页 / PDF 55 页：正常/缩减模式、关节、速度、力、动量、安全 I/O 和安全空间限制由控制器安全配置约束，不应由本项目放宽。
- 软件手册正文 153 页 / PDF 161 页：厂商网页自身的 3D 模型也依据机械臂状态同步显示，印证了使用实际关节角驱动数字孪生的方案。
- 软件手册正文 155 页 / PDF 163 页：控制器内的真实/模拟机器人切换只能在本体断电时进行；本项目的 `--robot-mode` 不能代替控制器侧该设置。
- 软件手册正文 179 页 / PDF 187 页：控制器网络可配置静态 IP 或 DHCP，静态地址不可使用 `192.168.0.0/.1/.255`。
- 软件手册正文 182 页 / PDF 190 页：物理急停按下后机械臂和电箱断电；普通 TCP 软件命令不能冒充这一能力。

`script_全解版(1).pdf` 可辅助理解切片和调用示例，但含 V5 遗留内容及明显笔误，例如 ConfigTCP 示例却调用 ReadTCP、变量名 `cc_clien`。发生冲突时，必须以 V6 正式通信协议、最新错误码文件和真机返回为准。

`CPS.py` 适合做命令名与参数顺序的参考，不建议原样进入生产链路，原因包括：

- 接收逻辑虽然会累积半包，但只检查累计字符串是否以分号结束，没有缓冲上限和按帧边界消费逻辑，也不能可靠处理一次 `recv()` 中的多帧和残留帧。
- 单次 10 秒超时可重试 5 次，故障发现时间不适合运动控制。
- 解码使用 `errors="ignore"`，可能悄悄丢失损坏字节。
- 部分等待运动代码会调用 `os._exit(0)`，不适合作为服务库。
- SDK 自带心跳与业务命令共用连接；真实网关需要更明确的优先级、超时和状态机。

首版可以复用其已核验的命令构造思路，但要实现一个小而严格、带测试夹具的新适配器。

## 3. 目标系统架构

```text
浏览器
  │ HTTPS / WebSocket：任务确认、状态、SOFA MJPEG
  ▼
远端 agent-web :8000
  │ 本机 HTTP：保持现有 RobotController 高层接口
  ▼
远端 robot-runtime :8001
  ├─ simulation provider ──> 当前 SimulationWorker + SOFA
  └─ real provider
       ├─ GatewaySession：命令、租约、审计、状态汇聚
       └─ RealMirrorWorker：实际关节角 ──> E05-Pro FK ──> SOFA/MJPEG
              ▲
              │ Mac 主动建立的加密长连接；结构化消息，不透传原始命令
              ▼
Mac robot-edge-gateway
  ├─ 状态机 / 单写者 / TTL / 幂等 / 本地看门狗
  ├─ 10004 DataSheet 50 ms 状态接收
  ├─ 10003 普通命令 FIFO（严格一个 in-flight）
  └─ 10001 允许列表内的快速读取（可选）
              │ 独立有线网，示例 192.168.0.20/24，无默认网关
              ▼
华沿控制器 192.168.0.10
              │
              ▼
E05-Pro 真实机械臂 + 现场物理急停/安全回路
```

### 3.1 远端服务器职责

- 解析用户输入，展示结构化命令并获取人工确认。
- 根据启动参数选择 `simulation` 或 `real` provider。
- 在真机模式维护唯一的已认证 Mac 网关会话和控制租约。
- 只下发版本化、高层、有限集合的命令，不生成厂家 ASCII。
- 保存命令生命周期：`created → accepted → executing → succeeded/failed/unknown/cancelled`。
- 聚合真实遥测并驱动被动 SOFA 数字孪生。
- 把“实际反馈”“命令目标”“视觉插值”分开标记；实际反馈永远是控制结果判定的依据。
- 网关掉线或状态过期时冻结最后一帧、显示明显告警并禁止新运动。

### 3.2 Mac 边缘网关职责

- 同时连接互联网和机器人独立有线网，但禁止网络桥接、Internet Sharing 和 IP forwarding。
- 主动连接远端，避免给公网开放 Mac 入站端口，更不能将 `192.168.0.10:10003` 暴露到公网。
- 对厂商协议执行严格编码、增量拆帧、响应命令名匹配、长度限制和超时管理。
- 保持普通命令单连接、单 FIFO、一个 in-flight；停止命令走最高优先级，但仍遵守控制器连接串行规则。
- 维护 10004 的最新有效状态，丢弃排队的旧遥测，避免网络恢复后“追赶历史画面”。
- 在下发前独立执行模式、状态、坐标、TCP、工作空间、速度、加速度、步长、命令期限和租约检查。
- 用本地单调时钟判断状态新鲜度和租约，不依赖控制器或远端服务器时钟绝对一致。
- 持久化近期命令 ID 与指纹，重连后拒绝重复运动；不因响应丢失而自动重发运动。
- 公网链路中断、遥测过期、状态异常或租约过期时，立即禁止新动作；若处于 `potentially_moving`，尽力从本地发送 `GrpStop` 并进入锁定故障态。
- 重连后只恢复只读状态，必须重新完成预检并由操作者显式重新取得控制租约。

### 3.3 控制器与现场职责

- 控制器的安全等级、缩减模式、关节限制、笛卡尔安全空间、碰撞阈值和安全 I/O 是第一层约束，本项目只能增加限制，不能降低它们。
- 首次阶段由操作者在厂家页面完成上电、使能和错误处理；网关只读取验证。厂商确认完整状态迁移流程后，才单独评审是否允许自动化上电/使能。
- 现场必须有受训操作者站在物理急停可触达的位置，并确保工作区清空、工具和线缆固定、速度处于缩减范围。
- 厂家网页可以用于监视和调试，但在网关取得控制租约期间，不允许另一名操作者同时从厂家网页、示教器或脚本发送运动命令。协议本身没有所有权机制，这一规则必须由流程和网关共同保证。

## 4. 运行模式与启动接口

### 4.1 对外命令行

统一入口计划改为：

```bash
# 兼容当前行为；未传 --robot-mode 时也默认 simulation
bash scripts/services/start_all.sh --robot-mode simulation

# 真机状态读取和数字孪生；默认 observe-only
bash scripts/services/start_all.sh \
  --robot-mode real \
  --real-config configs/robot-real.local.yaml

# 后续在所有运动门禁通过后才允许使用
bash scripts/services/start_all.sh \
  --robot-mode real \
  --real-config configs/robot-real.local.yaml \
  --real-control enabled
```

参数规则：

- `--robot-mode` 仅接受 `simulation|real`；缺省为 `simulation`，保证当前启动方式不回归。
- `--real-config` 在 `real` 模式必填，在 `simulation` 模式出现时直接报错，避免误读真机配置。
- `--real-control` 仅接受 `observe-only|enabled`，缺省为 `observe-only`。
- `enabled` 只代表服务器可以接收运动申请，**不代表立即可运动**；Mac 本地仍须处于 `ARMED`、租约有效且每条命令通过预检。
- 不提供“自动连接后立即使能/复位/运动”参数。
- 启动日志和网页顶部必须用高对比色显示 `SIMULATION`、`REAL / OBSERVE ONLY` 或 `REAL / ARMED`，不能只在隐藏环境变量里体现。

`scripts/services/start_all.sh` 是整套服务的规范启动入口；`agent/main.py` 的独立 CLI 也应增加同名 `--robot-mode` 供诊断使用。脚本把选定值传给所有服务；如果命令行、`RUNTIME_MODE`、robot-runtime provider 或网关握手报告互相冲突，启动/运动预检必须失败，不能静默选择其中一个。

### 4.2 服务启动行为

`simulation`：

- 启动当前四项服务：推理 `23333`、planner `8002`、SOFA/robot-runtime `8001`、agent-web `8000`。
- `robot-runtime` 选择 simulation provider，内部仍使用当前 `SimulationWorker`。
- 保持当前 REST、WebSocket、MJPEG、相机控制、命令确认和测试行为。
- 保留 `/api/.../simulation/...` 兼容路由，新增的通用 `/api/.../robot/...` 与其返回相同数据。

`real`：

- 同样启动 Xvfb 和 SOFA，因为网页仍需显示数字孪生。
- `robot-runtime` 选择 real provider，等待 Mac 网关主动连接。
- 网关未连接时服务可以启动，但 health 必须是 `degraded/not_ready_for_motion`，不能谎报全系统健康。
- SOFA 使用最新真实关节角被动更新；没有新数据时不自行运动，也不把命令目标当成当前姿态。
- agent-web 使用同一个通用 HTTP controller，不再直接依赖名为 `RobotSimulationHTTPController` 的具体类。
- planner 仍只生成不可执行的路径预览，`PUNCTURE_EXECUTION_ENABLED` 必须继续为 `false`。

### 4.3 配置隔离

## 5. Mac 与机械臂网络方案

### 5.1 本地双网络

推荐初始配置：

- Mac 有线口：选择未占用的 `192.168.0.x/24`，例如 `192.168.0.20/24`；不设置默认网关和 DNS。
- 机器人控制器：保持现场已验证的 `192.168.0.10/24`。
- Mac Wi-Fi 或第二网口：保持访问远端服务器的默认路由。
- 不开启 macOS Internet Sharing、桥接或 IP 转发。
- 用 `route get 192.168.0.10` 和 `route get <远端服务器>` 分别确认走有线口和公网口。
- 在运动前检查地址冲突；`192.168.0.20` 只是示例，不可盲目设置。

`192.168.0.10` 是本台控制器当前现场配置，不是通信协议规定的固定地址；网关从现场配置读取并与允许列表核对，不在代码中散落硬编码。

只读联调先验证：

```bash
ping 192.168.0.10
nc -vz 192.168.0.10 10003
nc -vz 192.168.0.10 10004
```

浏览器访问厂家页面只用于确认网络和现场状态，不通过抓取或模拟该网页来控制机器人。正式集成使用公开 TCP 协议，避免依赖厂商网页内部接口。

### 5.2 Mac 到远端服务器

开发联调阶段推荐使用 SSH 本地转发，让远端 `robot-runtime` 继续只绑定回环地址：

```bash
ssh -N \
  -L 18001:127.0.0.1:8001 \
  <user>@<remote-server>
```

Mac 网关再主动连接 `ws://127.0.0.1:18001/v1/gateway/connect`。SSH 断开即视为云端控制租约丢失。

稳定部署阶段改为以下之一：

- 首选：受认证的 `wss://` 长连接，双向 TLS，服务端只接受登记过的 Mac 客户端证书。
- 可选：WireGuard/企业 VPN 后继续使用 TLS 应用层认证。

无论使用哪种方式，都必须满足：

- 由 Mac 主动出站连接。
- 命令和遥测使用不同的逻辑消息类型和独立有界队列；停止类消息优先。
- 遥测采用 latest-wins，网络拥塞时丢旧帧，不无限缓存。
- 命令可靠送达，但过期命令不执行；断线后不自动重放。
- 连接建立时双向交换协议版本、gateway ID、启动随机 session nonce、机器人型号与控制器版本。

## 6. HansRobot TCP 适配器设计

### 6.1 三条控制器连接

第一版网关维护以下独立连接：

1. `10003` 普通命令连接：所有改变状态的命令及普通查询，严格串行。
2. `10001` 快速命令连接：启动后由 `ReadFastCmdPort` 查询实际端口；只开放 V1.0.19.1 正文逐条标注“可使用快速命令端口”的只读命令静态允许列表。
3. `10004` DataSheet 连接：连续接收 50 ms JSON 状态帧。

若 `10004` 不可用，可暂时用 `10001` 上的 `ReadRobotState`、`ReadCurFSM`、`ReadActPos` 降级读取，但必须降低频率并把状态标记为 degraded。不能一边订阅 20 Hz DataSheet，一边无节制高频轮询；错误码中已有“实时控制器服务负荷过高”。

`ReadCmdList` 只出现在随附 `CPS.py`，没有出现在 V1.0.19.1 正式协议正文，所以不能作为首版能力发现的必需步骤。只有在 PackageVersion 已进入支持矩阵且厂家确认该命令后，才可把它作为诊断信息；即使返回成功，也不能扩大代码内的官方静态允许列表。

普通连接的“单 in-flight”还意味着：停止请求可以清除尚未发送的队列，却不能越过同一 socket 上正在等待响应的请求。首版不得自行假定第二条写连接能安全抢占；必须向厂家确认是否支持专用停止连接、多客户端写入时的顺序和仲裁。在获得答案前，`motion_accept_response_timeout_ms` 必须现场量化并设得足够短；一旦停止无法在 `stop_delivery_timeout_ms` 内送达，就立即显示“软件停止请求未送达，请使用现场物理急停”，不得伪装成已经停止。

### 6.2 普通命令编解码

发送器必须：

- 只允许代码内定义的命令枚举，禁止外部传入命令名。
- 参数按每条命令的强类型模型编码；名字和 ID 只允许受限 ASCII，拒绝逗号、分号、控制字符和超长字符串。
- 所有发送帧严格以 `,;` 结束，不把多个命令拼到一次发送中。
- 维护最大命令长度和发送超时。

接收器必须：

- 使用字节缓冲增量查找终止符，正确处理半包、粘包、一次 `recv()` 多段和连接关闭。
- 发送端始终使用 `,;`。接收端以 `,;` 为规范终止符；考虑到正式文档个别失败模板漏写结束前逗号，可以在整帧其余结构完全合法时兼容末尾单独 `;`，同时记录 `protocol_deviation`，不能静默放宽其他格式。
- 对回显命令名与当前唯一 in-flight 请求进行匹配。
- 区分 `OK`、`Fail` 和协议错误；`Fail` 至少解析命令名、状态和整数错误码，剩余字段作为原始说明保留，避免说明内逗号导致错位。
- 不用 `errors="ignore"`。先按 ASCII/UTF-8 严格解码，无法解码时保存有限十六进制摘要并进入协议故障态。
- 对意外残留帧、未知状态、超长帧和格式冲突失败关闭，不猜测执行结果。

普通命令的 TCP 返回和机器人动作完成是两件事：

- `accepted`：控制器返回 `OK`，仅代表命令已受理。
- `executing`：在 `motion_start_timeout_ms` 内从 FSM/实际状态观察到运动，并用 `ReadCurWayPointID` 核对为本次短 ID；若下发前已经稳定处于目标公差内，则可走“无需运动”的独立完成分支。
- `succeeded`：在 `motion_completion_timeout_ms` 内运动结束、无错误、到位，本次 WayPoint ID 没有被其他写入者取代，且实际基座 TCP 在位置与姿态公差内持续满足批准的样本数和 dwell 时间。
- `failed`：控制器返回 Fail，或运动期间出现错误、急停、光幕、掉电、掉使能等。
- `unknown`：发送后连接中断或响应丢失，无法判断是否执行。该状态下禁止自动重发，先停止并由操作者核对实际姿态。

`OK` 后未在启动期限内开始、超过运动期限仍未完成、或停止未在各自送达/确认期限内完成，都必须结束等待并进入相应的 `failed`/`unknown` 与锁定态；绝不无限轮询。`ReadCurWayPointID` 是归属交叉验证，不替代 FSM、实际姿态和安全状态；真机若不支持或返回语义异常，则在厂家澄清前不开放真实运动。

### 6.3 DataSheet 解析

解析状态机：

```text
SEARCH_MAGIC -> READ_HEADER -> VALIDATE_LENGTHS -> READ_JSON -> VALIDATE_SCHEMA
     ^                                                        │
     └────────────── bounded resynchronization on error ──────┘
```

实现要求：

- 魔数严格为 `4C 54 42 52`（`LTBR`）。
- 头部固定 12 字节；协议已说明“总长”为表中所有字段之和，即包含头部和 JSON。长度字段的字节序未说明，必须用真机抓包/厂家答复确认，并验证实机总长符合文档后保存 golden fixture。
- 设置合理最大帧，例如 1 MiB；长度越界立即断开并告警。
- JSON 中许多数值可能以字符串出现，统一做有限数检查，禁止 NaN/Infinity。
- 核心数组必须至少包含 12 个 `Actual_Position` 值，关节数必须等于 6；错误维度不截断凑数。
- 每帧记录控制器 `MsgTitle.Stamp`、Mac 收包 wall clock 和 Mac monotonic time。
- 状态变化和错误帧不得被遥测降采样丢弃；普通姿态帧可以 latest-wins。

首版必取字段：

- `PosAndVel.Actual_Position[0:6]`：实际 J1～J6，度。
- `PosAndVel.Actual_Position[6:12]`：当前 UCS/TCP 下实际笛卡尔位姿。
- `PosAndVel.Actual_PCS_Base`：基座下实际 TCP 位姿。
- `PosAndVel.Actual_PCS_TCP`；注意 DataSheet 没有给出当前 TCP/UCS 的名称。
- `Actual_Joint_Velocity`、`Actual_Joint_Acceleration`、`Actual_Override`。
- `StateAndError.robotState`、`robotEnabled`、`robotMoving`、`robotPaused`、`robotBlendingDone`、`InPos`。
- `StateAndError.Error_Code`、`Error_AxisID`、各轴错误、`AutoMode`、`BrakeState`、`IsReduceMode` 和 `IsFreeDriveMode`。
- `FTData.FTControlState`；启动、每条运动前以及运动期间按实测批准频率，用普通命令连接上的 `ReadEmergencyInfo` 取得 `nESTO_Error`、`nESTO`、`nSafeGuard_Error`、`nSafeGuard`，不能只看“急停/光幕是否激活”而漏掉双通道回路故障。读取失败或结果过期同样失败关闭。
- `SystemInfo.DeviceSN`（若到场固件提供有效值），并与铭牌和现场资产台账交叉核对。

每秒或在状态改变时，用快速读取命令交叉检查一次 `ReadRobotState` 与 `ReadCurFSM`。启动和每次运动前还要读取 `ReadCurTCP`、`ReadCurUCS`，并与 `ReadTCPByName(needle_tip)`、`ReadUCSByName(Base)` 的六维值比较；也可用 `ReadActCoord(Base, needle_tip)` 直接读取指定坐标组合下的实际位姿。若 DataSheet 与命令查询长期不一致，或当前 TCP/UCS 无法确认，进入 `FAULT`，而不是任选一个继续运动。

### 6.4 高层命令到厂商命令的映射

`get_state`：

- 返回最新且未过期的 DataSheet 状态。
- 必要时合并 `ReadRobotState`、`ReadCurFSM`、`ReadAxisErrorCode` 和 `ReadEmergencyInfo`。
- 返回数据源时间、Mac 收包时间、新鲜度和连接质量，不能只有一个笼统的 `connected=true`。

`move_relative` 首个可动版本：

- 只接受 `robot_base` 下单轴小位移。
- 只有当前 TCP/UCS 的六维值已经分别与命名 `needle_tip`/`Base` 配置一致时，才可以最新 `Actual_PCS_Base` 为起点；否则用 `ReadActCoord(Base, needle_tip)` 得到指定坐标组合下的实际起点，任何比对失败都拒绝运动。
- 在 Mac 基于这个最新实际起点重算绝对目标 XYZ，保持实际 Rx/Ry/Rz 不变；不能使用用户确认时几秒前的起点直接计算相对目标。
- 使用 `WayPoint` 的直线模式、显式 TCP 名、显式 UCS `Base`、安全速度、已验证加速度、半径 0、无 seek。
- `nMoveType=1` 的直线 WayPoint 中，协议明确 dJ1～dJ6 无效，因此按协议填 0，不能把它们当逆解参考关节下发。
- 下发前可调用控制器 `GetInverseKin`，用最新实际关节作为该查询的参考解，验证终点解；再用经过真机校准的项目 FK/IK 对直线路径采样做第二层检查。查询结果不作为直线 WayPoint 的 dJ 字段，两套检查不一致时拒绝。
- 厂商命令 ID 使用网关生成的短 ASCII ID，并在网关维护它与全局 UUID 的映射。
- 不首选 `MoveRelL`，因为它没有在该命令中显式给出速度，且行为受当前 UCS/ToolMotion 状态影响；显式绝对目标更易审计。

`move_to_entry`：

- 当前真实后端必须先返回 `OPERATION_NOT_ENABLED`，直到契约提供经过校准的完整目标姿态。
- 不能把 `orientation_policy="configured_safe_orientation"` 当作已验证姿态。
- 后续应改为强类型 `Pose6D` 或 `Pose + OrientationPolicy`。若根据“入点 → 靶点”确定针轴，还需要明确绕针轴的 roll、进近方向、避障路径、奇异点和工作空间，不能只计算一个方向向量就执行。
- 通过评审后同样使用 `WayPoint` 直线/安全进近策略，并以实际到位结果验收。

`stop`：

- 映射到 `GrpStop,robot_id,;`，并在状态流确认运动停止。
- 它只是通过普通 IF TCP 发送的尽力而为软件停止请求，不属于已证明的安全功能。

当前 `emergency_stop`：

- 仿真模式保留原有锁定语义。
- 真机 provider 不得把现有 `EMERGENCY_STOP` 直接映射成 `GrpStop`，否则当前 orchestrator 会错误地要求返回 `estop/ESTOP` 并把普通停止伪装成硬急停。
- 新增独立的 `CommandIntent.SOFTWARE_STOP_REQUEST`、`ToolName.ROBOT_SOFTWARE_STOP_REQUEST` 和结果类型。它走最高软件优先级、内部调用 `GrpStop`，结果分别表达“是否送达”和“是否从反馈确认已停”，绝不设置 `physical_estop_active=true`。
- 网页红色快速按钮以及真机模式的语音/手势“急停”短语应生成这一新 intent，按钮文案为“立即请求软件停止（非安全功能）”。只有仿真模式继续生成现有 `EMERGENCY_STOP`。
- 在没有经过安全认证的硬件接口时，真实 provider 对现有 `EMERGENCY_STOP` 返回 `OPERATION_NOT_ENABLED`，不能通过兼容映射绕过。
- 真正的 `physical_estop_active` 只从 `ReadEmergencyInfo`/`ReadRobotState` 读取。
- 若未来接入经过安全认证的硬接线远程安全回路，必须作为独立项目评审，不能复用普通 TCP 命令语义。

`reset_estop`：

- 仿真模式继续重置仿真锁存。
- 真机物理急停必须由现场解除按钮、确认环境安全，再按厂商流程复位/上电；网页不能“一键清除物理急停”。
- `GrpReset` 只允许在错误原因已消除、现场操作者确认、错误策略明确允许时执行一次，禁止循环自动复位。

首版明确禁用：

- `StartServo`、`PushServoJ/P`、`SpeedJ/L`。
- 长点动 `MoveJTo/MoveLTo` 和依赖持续 `LongMoveEvent` 的操作。
- 任意脚本执行、IO 写入、TCP/UCS 写入、碰撞等级和安全参数修改。
- 自动上电、自动使能、自动切换控制器真实/模拟模式。
- 自动穿刺、力控推进和外部跟踪闭环。

设计要求：

- `RobotState.mode` 必须由真实 provider 设置为 `REAL`，同时另存控制器 `IsSimulation` 原始值；二者不一致时禁止运动。
- `connected` 必须拆成网关、DataSheet、命令端口、电箱连接等状态，不能用单个布尔值掩盖故障。
- `estop` 拆成只读的 `physical_estop_active` 和独立的 `software_stop_request_state`；普通 TCP 停止请求不会制造物理急停状态，保留旧字段时只能作为兼容派生值。

- 四元数在本项目内继续统一为 `xyzw`；若厂商转换接口返回 `wxyz`，只在适配器边界转换并做单元测试。
- 所有可选字段缺失都要显式为 unknown，不允许默认为安全状态。
- `state_age_at_gateway_send_ms` 由 Mac 用“本帧收包 monotonic → 发送瞬间 monotonic”的差计算；服务器只追加会话测得的保守传输耗时以及本地收包后的驻留时间，得到供显示的 `state_age_ms`。运动门禁始终使用 Mac 本地 monotonic age，绝不拿控制器、Mac、服务器的 wall clock 直接相减判断状态是否安全。

### 7.2 命令信封

远端到 Mac 的每条请求至少包含：

```json
{
  "schema_version": "1.0",
  "gateway_session_id": "...",
  "command_id": "UUID",
  "command_kind": "move_relative",
  "created_at_ms": 0,
  "expires_at_ms": 0,
  "based_on_robot_state_sequence": 0,
  "expected_start_pose_robot_base": {},
  "expected_tcp_name": "needle_tip",
  "expected_ucs_name": "Base",
  "payload": {},
  "safety_limits": {},
  "operator_confirmation_id": "..."
}
```

网关处理顺序固定为：

1. 验证会话、证书、schema、命令种类和所有有限数。
2. 检查 `command_id` 是否已见过；相同 ID/相同指纹返回缓存结果，不重复运动；相同 ID/不同指纹直接冲突。
3. 校验服务器签发的 `created_at_ms/expires_at_ms`；要求两端 NTP 正常且握手测得的时钟偏差在阈值内，按 Mac wall clock 计算剩余 TTL、再转换为本地 monotonic deadline 并限制最大值。时钟不可信或已经过期就拒绝。
4. 检查当前状态不早于 `based_on_robot_state_sequence`，并核对起始位姿漂移、TCP/UCS 和安全状态；状态序号持续增长是正常的，不能要求与服务器看到的序号完全相等。
5. 执行全部本地运动门禁。
6. 生成厂商短命令 ID，保存全局到本地映射。
7. 串行发送并分别上报 `accepted` 与实际完成结果。

普通运动请求按上述全部步骤处理。`SOFTWARE_STOP_REQUEST` 使用单独的受限流程：仍校验网关身份、schema、`command_id` 幂等、速率限制并完整审计，但显式豁免 `ARMED`、运动租约、普通运动 preflight 和人工确认；否则恰在租约丢失时会无法停机。网关本地看门狗即使云端已断开也必须能产生同一停止请求。

停止请求立即撤销 ARMED、阻止新动作、清除尚未发送的普通队列并把当前动作标记为取消中；但它仍可能被 `10003` 唯一 socket 上已经 in-flight 的请求阻塞。socket 可用时优先发送 `GrpStop`，分别报告 `delivery=sent|not_sent|unknown` 和 `motion_stop=confirmed|unconfirmed`。若超过停止送达或确认期限，必须立即报告“停止请求无法送达/无法确认”，提示现场物理急停，不能显示“已停止”。

### 7.3 错误模型

新增厂商错误上下文，不把数百个 vendor code 粗暴压缩成一个 `INTERNAL_ERROR`：

```text
stable_error_code             项目稳定错误码
vendor_error_code             厂商整数错误码
vendor_error_message          厂商原文或 GetErrorCodeStr 结果
vendor_error_axis             0～6 / unknown
fsm_code
recoverability                retry_after_state_change | operator_action | vendor_support
execution_certainty           not_sent | rejected | accepted | unknown | completed
raw_response_digest           有界摘要，不保存无限数据
state_snapshot
```

恢复策略按明确列表管理，不能只按数字区间猜测：

- 格式/参数/TCP/UCS 不存在：拒绝，不重试，修正配置或请求。
- busy/上一命令未返回：重新读取状态，绝不并发发送运动。
- 急停、光幕、3PE、安全参数校验：需要现场人工处理。
- 未上电、未使能：首版只提示操作者在厂商页面处理，不远程自动改变。
- 运动错误：确认原因消除后，按批准流程最多执行一次 `GrpReset`。
- EtherCAT、控制器内部错误、持续复位失败和未知错误：锁定为 `FAULT`，联系厂家。
- 发送后响应丢失：标为 `execution_certainty=unknown`，禁止自动重发。

首批必须写入测试夹具和错误策略的厂商码：

- 协议/连接：`20005/20006/20007`（命令、参数、格式错误）、`20008`（上一命令未返回）、`20035`（Socket 未连接）、`20037/20038`（连接/接收超时）、`20099`（当前 Socket 不允许该命令）、`20700/20701/20702`（TCP 接收、通信、连接关闭）。
- 运动前置：`20003`（主站未运行）、`20012`（未上电）、`20020`（未使能）、`20018/40102`（当前状态禁止）、`20021`（自碰撞风险）、`20029/20030`（TCP/UCS 不存在）、`20039`（光幕未清除）、`20057`（急停未清除）。
- 控制器侧状态：`40029`（未使能）、`40053`（未上电）、`40054`（急停）、`40055`（安全光幕）、`49601/49602`（笛卡尔姿态/关节目标越限）、`49621/49622`（异常停止/正在停止）。

错误码文件比控制协议发布日期更新，且未来还会新增状态。任何未识别 vendor code 默认归为不可自动恢复的 `FAULT`，同时保留原始整数供厂家定位。

## 8. 坐标系、姿态与数字孪生标定

### 8.1 坐标系定义

本项目必须显式区分：

- `B`：真实机器人控制器的 Base 基座坐标系。
- `F`：真实机器人末端法兰坐标系。
- `T`：安装后针具的 TCP/针尖坐标系，计划命名 `needle_tip`。
- `S`：SOFA 场景世界坐标系。
- `N`：未来导航、患者或医学影像坐标系；当前尚未建立到机器人基座的注册。

记 `^A T_B` 为把 B 坐标变换到 A 坐标的刚体变换，则数字孪生链路为：

```text
^S T_T = ^S T_B · ^B T_F(q_visual) · ^F T_T
```

真实关节角到可视关节角的初始标定模型为：

```text
q_visual[i] = sign[i] · deg2rad(q_robot[i] - zero_offset_deg[i])
```

如果项目命令声明为 `robot_base`，只有在 `project_robot_base == B` 已被验证并留档后才能直接把 XYZ 送给控制器。即使两者最终为单位变换，也要在配置中显式记录，不能靠默认假定。

未来来自医学影像/患者坐标系的点必须经过独立注册：

```text
p_B = ^B T_N · p_N
```

`^B T_N` 必须带注册方法、标定时间、使用设备、残差、有效期和操作者信息。它不能与 UCS、TCP 或 SOFA 相机坐标混为一谈。当前项目默认 `robot_base`，所以本次对接不得把图像像素或患者坐标直接当成机器人毫米坐标。

### 8.2 单位与旋转

- 项目外部距离为 mm，SOFA 内部场景单位为 m；沿用现有 `MM_PER_SCENE_UNIT=1000` 的唯一转换边界。
- 厂商 ACS 和 Rx/Ry/Rz 为度；项目 FK 内部使用弧度。
- 软件手册说明笛卡尔姿态为 XYZ 固定角，但仍需用真机 `RPY2Quaternion`、`Quaternion2RPY` 和若干已知姿态验证具体乘法顺序、符号和奇异位置行为。
- 厂商接口若输出 quaternion `wxyz`，项目契约是 `xyzw`；必须有显式适配函数，禁止直接切片复用。
- 首次数字孪生只使用实际关节角驱动连杆，避免笛卡尔逆解多解。`Actual_PCS_Base` 是“Base 下当前控制器 TCP”的位姿，只有项目 FK 使用同一个已验证 TCP 变换时才能拿它做残差比较。

### 8.3 六轴映射标定步骤

标定在缩减模式、低速、空旷台架和现场急停监护下完成：

1. 记录机器人型号、序列号、控制器 PackageVersion、`GetBaseInstallingAngle` 读回值、当前 TCP/UCS 和零位定义；用 `ReadPayload` 核对负载，但不由网关写配置。
2. 在一个远离关节限位和奇异点的安全姿态记录 J1～J6、厂家网页截图和 SOFA 截图。阶段 4 尚未标定最终针具，因此由现场在厂家页面选择并核验一个已知的零 TCP，使用 `ReadActCoord(Base, <zero_tcp>)` 比较法兰；若只能使用已验证的临时 TCP，则必须在项目 FK 中使用其同一份 `^F T_T`，不得使用仿真的临时 150 mm。
3. 每次只让一个关节沿厂家定义的正方向移动一个小角度，其他轴保持不动；分别确定关节顺序、旋转轴、正负号和模型零偏。
4. 至少采集“基准姿态 + 六个单轴姿态 + 多个组合姿态”，保存为可回归的 calibration dataset。
5. 用标定后的关节角运行项目 `E05ProKinematics.forward`，先按第 2 步的同一零 TCP/指定 TCP 比较法兰。最终 `needle_tip` 的 TCP 残差留到阶段 5 标定后重新验收。
6. 若误差不是固定刚体变换，停止继续运动，检查 E05-Pro 力控版本几何、J6 到法兰 184 mm 修改、关节原点和 xacro 版本；不能用随意平移把问题掩盖。
7. 若误差可由固定 `^S T_B` 解释，计算后在多个未参与拟合的姿态上验证。
8. 把 `joint_sign`、`zero_offset_deg`、`^S T_B`、样本、残差和审批人写入版本化标定记录。

数字孪生工程验收的初始目标可设为：

- 网页显示关节角与厂家反馈逐轴误差不超过 0.1°；由于同源采样，持续超限说明映射或时序错误。
- 阶段 4 的项目 FK 法兰与控制器同基准法兰残差、以及阶段 5 项目 `needle_tip` 与控制器同名 TCP 残差，位置目标均不超过 1 mm，姿态目标均不超过 0.5°。
- 这些是首轮软件/模型一致性目标，不是医疗定位精度声明；最终阈值必须结合厂家精度指标、针具标定和导航系统误差预算重新批准。

### 8.4 TCP、负载与安装角度

真机运动前必须同时完成：

- 安装最终针架或等效测试工具后，按厂家流程标定命名 TCP `needle_tip`。不能使用仿真的临时 150 mm。
- 通过多点法或已知尺寸方法重复标定，保存原始点和残差；另做 TCP 方向标定。
- 使用读取命令核对控制器中该 TCP 的六维值，并与本地只读配置一致。
- 配置真实工具质量、重心和必要的惯量参数；错误负载会影响碰撞检测、动力学和安全。
- 核对机座安装角度与真实安装方式一致。
- 用 `ReadPayload` 和 `GetBaseInstallingAngle` 分别只读核对负载/重心和安装角；任一值与审批配置不符就禁止运动。
- 固定使用显式 TCP 名和 UCS `Base`；不依赖厂家网页里“当前选中”的可变状态。
- 禁止网关在正常启动时自动写 TCP、UCS、负载、安全限制或安装角度。

### 8.5 被动 SOFA 镜像

为 `EntryPointReachEnv` 增加外部状态模式，建议职责拆分为：

- `ContinuousTrajectoryController`：只服务 simulation provider，保持当前行为。
- `ExternalJointStateController`：只接收已验证的 6 轴实际角度和真实状态，不执行 IK，不生成动作。
- `EntryPointReachEnv.apply_external_joint_state(...)`：通过现有 `E05ProKinematics.forward` 更新六个 link 和法兰；只有 TCP 已标定且身份已核验后才更新针具和 TCP marker。

真机镜像规则：

- 模型姿态只由最近的有效 `joint_positions_deg` 更新。
- DataSheet 的 TCP 数值面板显示控制器 `Actual_PCS_Base`，并明确标注这是“当前控制器 TCP”；最终工具未标定前隐藏 TCP marker，或固定显示 `UNCALIBRATED / 不可用于控制`。只有控制器当前 TCP/UCS 与本地已验证配置数值一致后，才显示同基准 `FK residual`。
- 真机轨迹由实际 TCP 样本生成，而不是从命令目标插值生成。
- 前端可在相邻的两帧实际关节样本之间做极短视觉插值，使 20 Hz 更平滑；插值只用于渲染，不能回流到状态判断或控制。
- 收到越界、NaN、错误维度或顺序倒退的数据时，保持最后一帧并显示红色 `STALE/INVALID`，不能让模型跳到零位。
- 网关重连后新 session 的首帧不能与旧 session 插值。

## 9. 实时性、心跳与失联策略

首轮工程指标，不作为安全等级承诺：

- 控制器 DataSheet 源周期：50 ms（20 Hz）。
- 网关到服务器姿态上送：最多 20 Hz，拥塞时 latest-wins。
- 服务器到网页遥测：目标 10～20 Hz；SOFA/MJPEG 按当前机器能力渲染。
- 机械臂采样到网页显示的端到端延迟：目标 p95 小于 250 ms。
- 网页必须显示 `source age`，而不是只显示“WebSocket 已连接”。

初始故障阈值建议：

- 10004 连续 250 ms 无有效帧：状态标记 `stale`，禁止新运动。
- `potentially_moving` 期间连续 300 ms 无有效状态：网关尽力发送 `GrpStop` 并锁定故障。
- 连续 1000 ms 无状态：标记 `disconnected`。
- 云端控制租约 1000 ms 未续期：禁止新命令；处于 `potentially_moving` 时执行同样的本地普通 TCP 软件停止请求策略。

这些值必须通过现场抓包、Mac 调度抖动和 WAN 延迟测试调整。真正决定能否继续运动的是 Mac 到控制器的本地状态新鲜度，不能因服务器或浏览器看起来流畅而放宽。

`potentially_moving` 必须在运动命令第一个字节发送前置为 true，直到通过本命令 WayPoint ID、FSM、`InPos` 和稳定姿态共同确认终态后才清除。即使反馈从未出现 `moving=1`，只要命令可能已到达控制器，就仍处在这个窗口；状态 stale、租约丢失、响应未知、超时或外部写入迹象均触发停止请求。这样可覆盖 `robotMoving` 自身约 50 ms 延迟和“已受理但尚未开始”的空窗。

心跳分三层：

- 控制器层：有效 DataSheet 帧是主要心跳；命令端口用低频只读查询/系统 TCP keepalive 辅助。
- 网关层：Mac 与服务器使用 ping/pong、session nonce 和租约。
- 浏览器层：显示服务器 WebSocket、网关、DataSheet、命令 socket 四层连接状态。

失联行为：

- 浏览器断开：服务器撤销该操作者的控制租约；处于 `potentially_moving` 的真机命令按批准策略请求停止，不能悄悄继续。
- 服务器与 Mac 断开：Mac 本地租约到期，禁止新动作；处于 `potentially_moving` 时尽力 `GrpStop`。
- DataSheet 断开：命令仍可通信也禁止继续运动；可用快速读做诊断，但不把长期降级当正常运行。
- 命令 socket 断开：立即锁定故障；若运动可能仍在继续，要明确显示“停止命令无法确认”，现场人员使用物理急停。
- Mac 进程重启：只读重连，不恢复旧租约，不重放任何命令。
- 控制器重启或 session 改变：所有旧命令 ID、状态和标定上下文失效，重新预检。

## 10. 真机安全状态机与运动门禁

Mac 网关建议使用以下显式状态：

```text
DISCONNECTED
  -> CONNECTED_OBSERVE_ONLY
  -> NOT_READY
  -> READY
  -> ARMED
  -> MOVING
  -> STOPPING
  -> READY

任意状态 -> PHYSICAL_ESTOP / SAFEGUARD / FAULT / STATE_STALE
故障恢复 -> CONNECTED_OBSERVE_ONLY（绝不直接回 ARMED）
```

每条真实运动下发时必须同时满足：

- 启动模式为 `real` 且配置允许控制。
- 控制器 `IsSimulation == 0`。
- 控制器启动完成，电箱连接正常。
- 本体已上电、已使能、抱闸状态符合厂家正常运行定义。
- 无 controller error、无轴错误。
- `ReadEmergencyInfo` 的 `nESTO_Error == 0`、`nSafeGuard_Error == 0`，并且无物理急停、无安全光幕/安全门触发；任一双通道回路不一致都按安全故障处理。
- FSM 为 33“机器人就绪”；不能处于运动、停止中、暂停、程序运行、零力示教或恢复安全空间。
- `AutoMode` 属于厂家确认并经现场批准的枚举；3PE 处于批准状态。若当前接口不能可靠读取 3PE，则在建立受信的硬件/现场确认机制前不开放运动。
- 台架联调要求缩减模式生效；`IsFreeDriveMode == 0`、`FTControlState == 0`，不能在零力示教或力控闭环中混入普通 WayPoint。
- DataSheet 为 fresh，命令 socket 健康，状态交叉检查一致。
- 当前 TCP/UCS 的六维值与批准的命名 TCP/UCS 读取值一致，机器人 DeviceSN/资产 ID、型号和 PackageVersion 与批准配置一致。
- 最终 TCP、`ReadPayload` 负载/重心、`GetBaseInstallingAngle` 安装角度和关节映射均已标定且读回一致。
- 目标坐标 frame 与单位明确；姿态策略已批准。
- 目标、整段直线路径和参考关节均在项目更严格的工作空间、关节、速度、加速度和步长范围内。
- 无另一个 active command，vendor controller 也未在运行其他程序。
- 命令未过期，当前状态不早于确认依据序号且起始姿态漂移在阈值内，command ID 未冲突。
- Mac 本地 `ARMED` 租约有效，现场操作者在场，远端任务已有独立确认记录。

任一字段为 unknown 都按不满足处理。

`ARMED` 不能由远端服务器单方面设置。台架阶段应由现场人员在 Mac 本地终端或仅绑定 `127.0.0.1` 的本地界面完成一次短时武装，输入当次测试编号并核对状态摘要；后续若接入硬件钥匙开关/安全 PLC，再替换为更可靠的本地授权信号。武装必须有短 TTL，执行完单个动作、控制链路中断、状态变 stale 或进入任何故障后立即失效，且不能自动重新武装。

协议本身没有独占写入锁。网关应持续读取 `ReadCurWayPointID`，并检测“当前 ID 不是本地 active command”“无本地命令却出现超出噪声阈值的姿态变化”或“程序/FSM 非预期变化”等外部写入迹象；发现后立即撤销 ARMED，处于 `potentially_moving` 时请求停止并要求现场核查。它只能作为检测和失败关闭，不能证明绝对独占；是否存在控制器侧独占远程模式仍须厂家确认。

完成判定必须综合：

1. 厂商立即响应为 `OK`。
2. 在批准的启动期限内观察到 FSM/`robotMoving` 进入运动，并用 `ReadCurWayPointID` 交叉确认本次短 ID；或下发前已经连续稳定处于目标公差内而明确走无需运动分支。
3. 运动期间始终无错误、急停、光幕、掉电或掉使能。
4. 在批准的运动期限内回到 READY/非 moving，`InPos=1`。
5. 实际基座 TCP 连续达到 `completion_stable_samples`，且满足 `completion_dwell_ms`，始终位于目标位置与姿态公差内。
6. 当前 WayPoint ID 未被外部写入替换，并记录最终实际关节、TCP、耗时和误差后才返回 `succeeded`。

不能仅凭 `WayPoint,OK,...,;` 返回成功，也不能在 moving 状态约 50 ms 的延迟窗口内误判“没有开始即已完成”。任一启动/运动/停止 deadline 到期都必须终止等待、请求停止并返回明确的超时/结果未知状态。

5. 将单次相对位移上限设为 1 mm、线速度不高于 2～5 mm/s、半径 0。

- 真实与 SOFA 关节/末端出现超阈值偏差。
- 机械臂出现异常声音、振动、线缆牵拉、接近限位、奇异姿态或非预期轨迹。

退出条件：

- 六方向与安全绝对位姿重复多次均正确。
- 响应、启动、运动、停止送达和停止确认的最坏实测时延及安全余量已记录；各 deadline 触发后不会无限等待或假报成功。
- 停止、响应超时、遥测断开和服务器断开故障注入均符合预期。

- 任一安全状态 unknown、stale、急停/光幕回路故障、错误、急停、光幕、非批准 AutoMode/3PE、非缩减模式、自由驱动、力控开启或非 READY 均不能运动。
- 停止请求可在 ARMED/租约/确认失效时触发，但仍经过认证、限流、幂等和审计。

### 13.2 集成测试

建立 fake controller，能脚本化以下行为：

- 正常 `OK`，延迟进入 moving，再正常到位。
- 立即 `Fail`。
- 返回 OK 但从不运动。
- 返回 OK 并运动，但 `ReadCurWayPointID` 是外部 ID，或本命令永不到位。
- 运动中错误/光幕/急停。
- 接受命令后关闭连接，制造结果不确定。
- DataSheet 分片、合并、损坏和暂停。
- `ReadRobotState` 与 DataSheet 不一致。

端到端覆盖：

- simulation provider 全量原测试。
- real observe-only：fake controller → fake/真实 Mac gateway → remote runtime → SOFA → web telemetry。
- real enabled：确认 → command envelope → `WayPoint` → 状态完成 → 结果回传。
- 浏览器重复确认、服务重启、网关重连不重复运动。
- stop 清除未发送队列；in-flight 阻塞、无法在期限内送达或无法确认停止时，结果都不是假成功。

## 15. 可观测性、安全与审计

每条命令至少记录：

- 用户/会话、输入来源、原始结构化命令摘要和人工确认 ID。
- server command ID、gateway short ID、gateway session nonce。
- 创建、下发、受理、开始、停止、完成各时间戳。
- 下发前和完成后的完整机器人安全状态快照。
- TCP/UCS、frame、目标姿态、速度、加速度、工作空间和配置哈希。
- 厂商原始返回的有界摘要、vendor code、FSM、最终实际位置和误差。
- 执行确定性：未发送、拒绝、已受理、结果未知、已完成。

指标与告警至少包括：

- DataSheet 周期、丢帧、解析错误、source age。
- Mac→server RTT、重连次数、租约过期。
- SOFA 帧率、机器人采样到网页的端到端延迟。
- 命令受理/开始/完成耗时、停止耗时、位置残差。
- 状态不一致、未知错误码、TCP/UCS/版本漂移。

安全要求：

- mTLS/SSH 认证；服务端按 gateway ID 授权。
- 远端用户鉴权和角色分离：观察者不能取得控制租约。
- 每次只允许一个控制租约；租约有短 TTL，可被现场优先撤销。
- 日志不保存私钥、令牌和完整证书；敏感医学图像与机器人审计分开管理。
- 机器人子网不对公网路由，控制器端口不做公网端口映射。
- 依赖和网关发布包固定版本并校验哈希。

## 16. 风险与对应措施

高风险：WAN 延迟或断线导致远程闭环失稳。

- 措施：只下发离散高层动作；状态门控、完成判断和失联停止在 Mac；禁用公网 Servo。

高风险：项目坐标/关节映射与真机不一致。

- 措施：先只读数字孪生；六轴单独标定；FK 与控制器在同一个已验证 TCP 基准下多姿态交叉验证；误差未过门禁禁止运动。

高风险：临时针尖 TCP 或错误负载导致碰撞/定位误差。

- 措施：真机独立配置、null 阻断、最终工具安装后重新标定、读取核对和配置哈希绑定。

高风险：把 `GrpStop` 当作物理急停。

- 措施：UI/契约/文档统一称为“普通 TCP 软件停止请求（非安全功能）”，并与 physical e-stop 拆分；现场硬急停始终可触达。

高风险：普通 TCP `OK` 被误认为运动完成。

- 措施：区分 accepted/executing/completed，设置启动/完成期限，以 WayPoint ID、FSM、实际状态、稳定样本和最终姿态完成闭环。

高风险：命令响应丢失后自动重试造成重复运动。

- 措施：单 in-flight、幂等账本、结果不确定态、断线不重放、人工核对。

高风险：厂家网页/示教器与网关同时控制。

- 措施：唯一控制租约、现场流程、检测非本地 WayPoint ID/无命令姿态变化/程序与 FSM 异常并立即撤销 ARMED；真机写入阶段停止其他写入者，同时向厂家确认是否存在控制器侧独占模式。

高风险：版本或厂商资料不一致。

- 措施：启动读取型号/PackageVersion，建立支持矩阵；正式协议优先于旧脚本；未知状态和错误 fail closed。

中风险：20 Hz 遥测使画面不够平滑。

- 措施：前端或 SOFA 只做视觉短插值；显示 source age；绝不把插值用于控制。

中风险：Mac 睡眠、切网或进程崩溃。

- 措施：受监督服务、运动期防睡眠、网络变化监控、短租约和本地停止；同时承认软件看门狗不替代硬安全回路。

## 17. 需要向厂家确认的问题

在首次写命令前取得书面或可追溯答复：

1. 到场控制器的准确 PackageVersion、机器人型号/变体是否与协议 V1.0.19.1 完全兼容。
2. `10004` DataSheet 两个 4 字节长度字段的端序，以及到场真机的 total length 实现是否符合“包含 12 字节头和 JSON”的文档定义。
3. 每个端口允许的最大客户端数，厂家网页打开时是否占用 IF/DataSheet 连接。
4. `AutoMode` 的完整枚举、3PE 状态和从外部 socket 执行各运动命令所需模式。
5. 推荐的开机、连电箱、上电、主站、复位、使能和关机顺序；首版是否应始终由现场页面操作。
6. `GrpStop` 对应的停止类别、减速度、命令 socket 断开时控制器是否继续当前 WayPoint；是否允许专用停止 socket，以及多客户端写入时的仲裁/顺序保证。
7. WayPoint 命令 ID 的字符集、长度、唯一性和查询方法。
8. Rx/Ry/Rz 的 XYZ 固定角精确定义、矩阵乘法顺序，以及 quaternion 返回是否确为 WXYZ。
9. E05-Pro 力控版准确几何/DH 或 xacro、关节零位/正方向，以及项目采用 184 mm J6→力控法兰尺寸是否正确。
10. 命名 TCP/UCS 的持久化读取/写入规则，控制器重启后的行为。
11. 安全光幕、物理急停、3PE 和远程控制的推荐接线与合规边界。
12. Servo 断流、退出和停止语义；本项目首版禁用，但后续评审必须有答案。
13. 是否有更新的官方 Python SDK、DataSheet schema 或协议勘误可替代当前 `CPS.py`。
14. 是否存在控制器侧独占远程控制模式，可阻止厂家网页、示教器、脚本和网关同时写入。

## 18. 最终验收标准

只有同时满足以下条件，才能声明“当前项目已完成真实机械臂基础对接”：

- 仿真模式默认行为和全部现有测试无回归。
- CLI 能可靠选择 simulation/real，日志、health 和网页不会混淆模式。
- Mac 网关通过认证的出站链路连接服务器，机器人端口未暴露公网。
- 真机状态、六轴关节、TCP、错误、FSM、急停/光幕及其双通道回路故障、AutoMode、缩减/自由驱动和力控状态可稳定读取。
- SOFA 只由实际关节反馈驱动，状态过期时正确冻结和告警。
- 关节/坐标/TCP/负载/安装角度标定有记录且通过批准阈值。
- 真机运动只有在双重门禁和现场确认后可达，任一 unknown/stale 状态均被拒绝。
- 普通 TCP OK 与实际完成明确分离，响应/启动/运动/停止均有有限 deadline；`potentially_moving`、WayPoint ID、命令幂等、过期和结果不确定路径经过测试。
- 普通 TCP 软件停止请求、物理急停和复位语义准确，停止送达/确认最坏时延已量化，现场物理安全回路已演练。
- 相对小步和批准的绝对安全位姿通过重复测试与故障注入。
- 外部 WayPoint ID、无本地命令却发生姿态变化等并发写入迹象能撤销 ARMED、失败关闭并留下审计记录。
- planner 仍只提供不可执行预览，穿刺执行保持关闭。
- 已完成只读长稳、低速重复运动、断线/崩溃/急停/光幕等故障测试并归档证据。

“完成基础对接”仍不等于获得临床使用资格，也不等于满足手术导航总精度。患者坐标注册、外部追踪、针具标定误差、碰撞/路径规划、力控穿刺、风险管理、法规与医疗验证均属于后续独立里程碑。

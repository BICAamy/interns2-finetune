# InternS2 智能体驱动的脊柱穿刺机械臂系统技术文档

> 文档状态：老师确认架构后的技术路线基线  
> 当前范围：InternS2 解析非结构化指令、机械臂定位到入点、对接外部穿刺路径规划工具  
> 仿真范围：只演示机械臂移动到入点，以及不带坐标的相对移动  
> 安全说明：当前仅用于科研仿真与算法验证，不用于真实患者、临床决策或真实机械臂自主穿刺  
> 最后更新：2026-08-13

## 1. 文档目的

本文根据老师确认的架构图，定义项目后续开发的唯一主线。

项目的核心不是让 InternS2 自己计算机械臂轨迹，也不是由本项目实现完整的穿刺路径规划，而是：

1. 用户或医生提供语言、手势以及其他非结构化数据；
2. 输入中通常包含入点坐标和靶点坐标；
3. InternS2 理解输入并转换为统一 JSON 结构化数据；
4. 智能体先调用机械臂移动工具，使针尖或机械臂工具中心点移动到入点；
5. 确认到达入点后，再调用学长开发的穿刺路径规划工具；
6. 路径规划工具接收入点和靶点，输出可以控制穿刺针从入点到靶点的数值；
7. 当前仿真只展示第 4 步，不实现针从入点穿刺到靶点的过程；
8. 如果指令只是“往上抬一点”，则直接执行相对移动，不要求提供入点和靶点，也不调用路径规划工具。

本文用于约束后续代码结构、接口、开发顺序和验收标准。若后续需求发生变化，应先修改本文，再修改实现。

## 2. 项目范围

### 2.1 当前需要完成

- 移除 NavGPT、R2R、viewpoint 和 DeepSeek NavGPT 适配；
- 使用当前 InternS2 作为智能体基底模型；
- 接收文本、语音、手势和可扩展的其他非结构化输入；
- 将非结构化输入解析为统一 JSON；
- 提取并校验入点坐标、靶点坐标、单位和坐标系；
- 根据任务类型选择并调用正确工具；
- 在仿真环境中连续展示机械臂移动到入点；
- 支持“上、下、左、右、前、后移动一点或 N 毫米”等相对移动；
- 为学长的路径规划工具建立稳定的适配接口；
- 在学长工具尚未完成时提供 Mock 工具，先打通调用链；
- 通过网页显示输入、解析结果、机械臂状态、仿真画面和工具调用结果；
- 保留以后接入真实机械臂的控制适配层，但默认禁止真实控制。

### 2.2 当前不需要完成

- 不由本项目研发穿刺路径规划算法；
- 不要求当前仿真展示针从入点穿刺到靶点；
- 不建模皮肤、软组织、针体形变或穿刺接触力；
- 不训练视觉伺服、强化学习或模仿学习控制策略；
- 不让 InternS2 直接生成关节角、力矩或高频控制量；
- 不根据普通二维手势自动计算医学三维入点或靶点；
- 不把普通 RGB 图像中的像素坐标直接当成机械臂三维坐标；
- 不在当前阶段连接真实患者或执行真实穿刺。

学长的路径规划工具完成后，本项目负责调用、结果校验和控制链路对接，但路径规划算法本身仍属于外部工具。

## 3. 老师确认后的总体架构

### 3.1 离线微调链路

```text
医疗数据
  → 数据清洗与指令构造
  → 使用 XTuner 对 InternS2 进行 LoRA 微调
  → 得到更擅长医学语义、坐标提取和工具选择的 InternS2
```

微调的目标是提高 InternS2 对医学描述和工具调用的理解能力，不是训练机械臂底层控制器。

当前阶段暂不进行微调，把现有 InternS2 视为已经准备好的基底模型，优先打通智能体、工具和仿真链路。

### 3.2 在线运行链路

```text
用户 / 医生
  │
  ├── 文本或语音
  ├── 手势 / 图像
  └── 含入点、靶点的其他非结构化数据
  │
  ▼
输入预处理
  ├── 语音 → ASR 文本
  ├── 手势 → 手势事件或图像语义
  └── 原始文本 / 多模态内容
  │
  ▼
InternS2
  ├── 理解用户意图
  ├── 提取入点和靶点
  ├── 判断信息是否完整
  └── 输出统一 JSON 结构化任务
  │
  ▼
智能体运行时：Schema 校验、坐标校验、状态机和工具调度
  │
  ├── 相对移动任务 ─────────→ 机械臂相对移动工具
  │                              └→ 仿真展示 / 未来实操
  │
  └── 入点 / 穿刺任务 ──────→ 机械臂移动到入点工具
                                 ├→ 仿真展示 / 未来实操
                                 └→ 到达入点后
                                      ▼
                               穿刺路径规划工具
                               输入：入点 + 靶点
                               输出：穿刺针控制数值
                                      ├→ 当前只接收或展示结果
                                      └→ 未来仿真 / 实操执行
```

### 3.3 最重要的执行约束

1. InternS2 只负责理解、结构化和选择工具。
2. 机械臂移动工具负责把机械臂针尖或工具中心点移动到入点。
3. 穿刺路径规划工具由学长团队提供，本项目不实现其算法。
4. 路径规划工具可以获得 JSON 中的入点和靶点，但穿刺控制不得在机械臂确认到达入点之前执行。
5. 机械臂未到达入点、定位失败或任务被停止时，禁止进入穿刺阶段。
6. 当前仿真在机械臂到达入点后即可完成演示，不要求执行穿刺路径。
7. 相对移动任务不需要伪造入点或靶点，也不调用路径规划工具。

## 4. 输入类型与任务分流

### 4.1 输入来源

系统支持以下输入来源：

- 直接文本；
- 语音经 ASR 得到的文本；
- 操作者摄像头拍摄的固定手势；
- 图片和文字组合；
- 包含坐标的病历描述、检查结论或其他非结构化数据；
- 后续经过授权接入的结构化医疗数据。

输入预处理模块只负责把数据转换为 InternS2 可以读取的形式。任务意图、坐标和工具选择由 InternS2 完成。

### 4.2 四类核心任务

| 输入情况 | 任务类型 | 系统行为 | 是否调用路径规划 |
|---|---|---|---|
| 有入点、有靶点，并明确要求穿刺 | `puncture` | 先移动到入点，到达后调用路径规划工具 | 是 |
| 只有入点，或只要求移动到入点 | `move_to_entry` | 移动到入点后结束 | 否 |
| “往上抬一点”等方向性指令 | `move_relative` | 按相对位移移动后结束 | 否 |
| 信息不足、矛盾或无法确认意图 | `clarify` | 询问用户，不产生运动 | 否 |

另外，停止和急停分别映射为 `stop` 和 `emergency_stop`，不需要坐标。

### 4.3 典型行为

#### 完整穿刺指令

用户输入：

> 入点是基座坐标系下 `(20, 35, 80)` 毫米，靶点是 `(24, 38, 120)` 毫米，请执行穿刺任务。

系统行为：

```text
提取入点和靶点
  → 校验坐标
  → 调用 move_robot_to_entry
  → 等待并验证已到达入点
  → 调用 plan_puncture_path(entry_point, target_point)
  → 当前版本显示路径规划返回值，不执行仿真穿刺
```

#### 只移动到入点

用户输入：

> 将机械臂移动到入点 `(20, 35, 80)` 毫米。

系统只调用 `move_robot_to_entry`，到达后任务完成。

#### 不带坐标的相对移动

用户输入：

> 往上抬一点。

系统行为：

```text
识别为 move_relative
  → 使用配置中的默认步长
  → 调用 move_robot_relative
  → 仿真机械臂向上连续移动
  → 任务完成
```

第一版将“上”定义为机械臂基座坐标系 `+Z`，将“一点”解析为配置项 `default_relative_step_mm`，建议仿真默认值为 5 mm。页面必须显示实际采用的方向、坐标系和距离。

#### 信息不完整

用户输入：

> 从这个位置开始穿刺。

若系统无法从当前上下文获得合法入点和靶点，应返回需要补充的信息，不得猜测坐标或调用机械臂。

## 5. InternS2 的职责

### 5.1 InternS2 负责

- 理解文本和 ASR 文本；
- 结合输入图像或手势事件理解用户意图；
- 从非结构化内容中提取入点和靶点；
- 判断是移动到入点、相对移动、完整穿刺、停止还是需要澄清；
- 生成符合 Schema 的 JSON；
- 根据工具返回结果决定是否进入下一阶段；
- 向用户说明解析结果、执行状态和失败原因。

### 5.2 InternS2 不负责

- 自己计算机械臂逆运动学；
- 自己生成连续轨迹或关节控制量；
- 自己实现穿刺路径规划；
- 绕过坐标、工作空间和状态校验；
- 自己决定连接仿真机械臂还是真实机械臂；
- 在缺少入点或靶点时编造坐标；
- 把自然语言内容直接拼接成底层控制字符串。

仿真或真实模式由系统配置决定，不允许 InternS2 通过模型输出切换。

## 6. 统一结构化数据

### 6.1 InternS2 输出 Schema

InternS2 对一条用户输入的解析结果统一为：

```json
{
  "schema_version": "1.0",
  "command_id": "cmd-0001",
  "intent": "puncture",
  "entry_point": {
    "x": 20.0,
    "y": 35.0,
    "z": 80.0,
    "unit": "mm",
    "frame": "robot_base",
    "source": "user_text"
  },
  "target_point": {
    "x": 24.0,
    "y": 38.0,
    "z": 120.0,
    "unit": "mm",
    "frame": "robot_base",
    "source": "user_text"
  },
  "relative_motion": null,
  "missing_fields": [],
  "needs_confirmation": true,
  "confidence": 0.98,
  "summary": "先移动至入点，再进行穿刺路径规划"
}
```

相对移动示例：

```json
{
  "schema_version": "1.0",
  "command_id": "cmd-0002",
  "intent": "move_relative",
  "entry_point": null,
  "target_point": null,
  "relative_motion": {
    "axis": "z",
    "direction": "positive",
    "distance_mm": 5.0,
    "frame": "robot_base",
    "distance_source": "configured_default"
  },
  "missing_fields": [],
  "needs_confirmation": false,
  "confidence": 0.96,
  "summary": "机械臂沿基座坐标系 Z 正方向移动 5 毫米"
}
```

### 6.2 字段约束

- `intent` 只能来自受控枚举：`puncture`、`move_to_entry`、`move_relative`、`stop`、`emergency_stop`、`clarify`；
- `puncture` 必须同时具有合法的 `entry_point` 和 `target_point`；
- `move_to_entry` 必须具有合法的 `entry_point`；
- `move_relative` 必须具有合法的 `relative_motion`；
- 坐标必须明确 `unit` 和 `frame`；
- `source` 用于记录坐标来自用户文本、结构化数据、图像标注还是其他输入；
- `confidence` 只用于辅助判断，不能代替确定性的参数校验；
- 运行时重新生成可信的 `command_id`，不直接信任模型生成的标识；
- JSON Schema 校验失败时不得调用任何运动工具。

### 6.3 坐标系和单位

第一版至少定义：

- `robot_base`：机械臂基座坐标系；
- `tool_center_point`：末端工具中心点坐标系；
- `needle_tip`：针尖坐标系；
- `simulation_world`：仿真世界坐标系；
- `scene_camera`：仿真相机坐标系。

第一版对外坐标和距离统一使用毫米 `mm`，内部按仿真器或机器人驱动的要求集中转换。禁止在不同模块中分别实现不同的单位换算。

机械臂“移动到入点”默认指针尖或已标定工具中心点到达入点，而不是机械臂法兰盘到达入点。具体 TCP 必须在配置中明确。

如果用户未说明单位或坐标系：

- 仿真模式可以采用页面明确展示的默认单位和默认坐标系，但必须在执行前显示解析结果；
- 真实模式必须要求确认或补充信息；
- 任何模式都不能把二维图像像素坐标直接当作三维机械臂坐标。

## 7. 智能体执行状态机

### 7.1 完整状态

```text
IDLE
  → PARSING
  → CLARIFICATION_REQUIRED（信息不足时）
  → VALIDATING
  ├→ EXECUTING_RELATIVE → COMPLETED
  └→ MOVING_TO_ENTRY
        ├→ FAILED
        └→ AT_ENTRY
              ├→ COMPLETED（只移动到入点，或当前仿真演示结束）
              └→ PATH_PLANNING（完整穿刺任务）
                    ├→ PLANNER_UNAVAILABLE
                    ├→ PLAN_FAILED
                    └→ PLAN_READY
                          └→ PUNCTURE_EXECUTING（未来阶段，当前禁用）

任意运动状态 → STOPPED
任意状态 → ESTOP
```

### 7.2 调度规则

完整穿刺任务的运行时逻辑必须等价于：

```python
parsed = intern_s2_parse(user_input)
command = validate_and_normalize(parsed)

if command.intent == "move_relative":
    return move_robot_relative(command.relative_motion)

if command.intent in {"move_to_entry", "puncture"}:
    move_result = move_robot_to_entry(command.entry_point)
    if not move_result.reached:
        return move_result

    if command.intent == "move_to_entry":
        return move_result

    plan_result = plan_puncture_path(
        entry_point=command.entry_point,
        target_point=command.target_point,
    )
    return plan_result
```

以上是行为约束，不要求直接照抄为生产代码。

当前仿真模式即使得到 `PLAN_READY`，也只显示和记录路径规划结果，不执行针体穿刺。以后是否进入 `PUNCTURE_EXECUTING`，由新增配置、安全机制和执行适配器共同决定。

### 7.3 失败传播

- 坐标校验失败：不调用机械臂；
- 移动到入点失败：不调用路径规划；
- 路径规划不可用：机械臂保持在入点或进入配置的安全状态；
- 路径规划返回非法数据：不执行穿刺；
- 用户停止或急停：取消当前任务和后续工具调用；
- 网络断开：当前仿真自动暂停；未来真实设备按设备安全策略停止。

## 8. 工具接口设计

### 8.1 查询机械臂状态：`get_robot_state`

不产生运动，返回当前 TCP 位姿、机器人状态、运行模式和急停状态。

```json
{
  "mode": "simulation",
  "tcp": "needle_tip",
  "position_mm": [0.0, 0.0, 100.0],
  "orientation_xyzw": [0.0, 0.0, 0.0, 1.0],
  "frame": "robot_base",
  "motion_state": "idle",
  "estop": false
}
```

### 8.2 移动到入点：`move_robot_to_entry`

输入：

```json
{
  "command_id": "cmd-0001",
  "entry_point": {
    "x": 20.0,
    "y": 35.0,
    "z": 80.0,
    "unit": "mm",
    "frame": "robot_base"
  },
  "tcp": "needle_tip",
  "orientation_policy": "configured_safe_orientation",
  "speed_mm_s": 5.0
}
```

输出：

```json
{
  "command_id": "cmd-0001",
  "status": "success",
  "reached": true,
  "final_tcp_position_mm": [20.1, 35.0, 79.9],
  "frame": "robot_base",
  "position_error_mm": 0.14,
  "trajectory_id": "traj-0001",
  "message": "机械臂已移动到入点"
}
```

第一版只验收位置到达。针的朝向采用配置的安全姿态；如果以后学长的路径规划工具要求入点处的特定姿态，再扩展接口，不由 InternS2 擅自计算。

### 8.3 相对移动：`move_robot_relative`

输入：

```json
{
  "command_id": "cmd-0002",
  "translation_mm": [0.0, 0.0, 5.0],
  "frame": "robot_base",
  "speed_mm_s": 5.0
}
```

该工具负责把一次相对移动拆为平滑、连续的小步运动。InternS2 不输出仿真控制周期中的每一个增量。

### 8.4 穿刺路径规划：`plan_puncture_path`

这是学长团队提供的外部工具。本项目只实现适配器、Mock、超时处理、输入输出校验和调用记录。

已确认的最小输入是入点和靶点：

```json
{
  "request_id": "plan-0001",
  "entry_point": {
    "x": 20.0,
    "y": 35.0,
    "z": 80.0,
    "unit": "mm",
    "frame": "robot_base"
  },
  "target_point": {
    "x": 24.0,
    "y": 38.0,
    "z": 120.0,
    "unit": "mm",
    "frame": "robot_base"
  }
}
```

输出是能够控制穿刺针从入点到靶点的数值。由于学长工具尚未完成，最终字段不能由本项目提前假定。适配层先使用版本化信封：

```json
{
  "request_id": "plan-0001",
  "status": "success",
  "planner_name": "external_puncture_planner",
  "planner_version": "TBD",
  "output_schema_version": "TBD",
  "control_mode": "TBD",
  "control_payload": {},
  "message": "路径规划成功"
}
```

`control_payload` 的正式结构必须与学长确认后冻结，可能是轨迹点、位姿序列、关节序列、速度序列或其他控制数值。未经确认，不能假设某一种格式并据此开发穿刺执行器。

路径规划适配器必须支持：

- `MockPuncturePlanner`：学长工具完成前用于打通流程；
- `ExternalPuncturePlannerClient`：以后对接 HTTP、gRPC、ROS 2 或 Python API；
- 版本检查；
- 超时和重试策略；
- 输入输出 Schema 校验；
- 原始结果留档；
- 禁止在输入输出校验失败时执行穿刺。

### 8.5 停止工具

- `stop_robot`：正常减速停止当前运动；
- `emergency_stop`：立即停止并进入锁定状态，不依赖 InternS2；
- `reset_estop`：由用户显式操作后解除仿真急停；
- `reset_simulation`：恢复仿真初始状态。

### 8.6 统一错误码

- `INVALID_COMMAND_SCHEMA`；

## 9. 仿真设计

### 9.1 当前仿真唯一目标

当前仿真只需演示：

1. 场景中存在已购买的华沿 E05-Pro 力控版完整六轴机械臂；
2. 末端具有可观察的针尖或 TCP；
3. 场景中显示入点标记；
4. 机械臂从当前位置连续、平滑地移动到入点；
5. 页面显示运动轨迹、当前位置、目标位置和最终误差；
6. “往上抬一点”等相对移动可以正确显示；
7. 仿真结束条件是到达入点或完成相对移动。

当前不需要在仿真中显示针进入组织，也不需要显示从入点到靶点的穿刺动画。

### 9.2 仿真技术基线

沿用 SOFA + LapGym/`sofa_env` 作为仿真技术基线，但只实现简化的 `EntryPointReachEnv`：

- `reset()`：重置机械臂、入点和相机；
- `set_entry_point(point)`：设置并显示入点；
- `move_to_entry(point)`：规划并执行连续定位运动；
- `move_relative(delta)`：执行相对移动；
- `get_state()`：返回 TCP 位姿和运动状态；
- `render()`：输出 RGB 帧；
- `stop()`：停止当前运动。

机械臂六轴关节链和网格来自厂家固定版本的 E05 新版 `485/elfin5` URDF/STL；力控版 J6 到法兰距离按厂家尺寸图修正为 `184 mm`。每个 TCP 路点必须通过完整六轴逆解并满足关节范围、关节速度限制，不能仅移动末端标记。法兰到针尖暂用局部 `+Z 150 mm` 的仿真配置，安装针架并完成 TCP 标定前禁止用于实机。

由于当前不做穿刺物理，第一版不引入 BeamAdapter、柔性针、组织 FEM 或接触力模型。仿真接口与具体引擎隔离，未来如更换为 Isaac Sim、MuJoCo 或其他机械臂仿真平台，不影响 InternS2 和工具协议。

### 9.3 仿真与真实机械臂统一适配

机械臂工具面向统一接口：

```text
RobotController
  ├── SimulationRobotController（当前实现）
  └── RealRobotController（未来实现，默认禁用）
```

智能体只能调用 `RobotController`，不能直接操作仿真器或真实机械臂驱动。运行模式来自服务器配置，不来自模型输出。

## 10. 语音、手势和指令优先级

### 10.1 语音

浏览器采集麦克风音频，使用独立 ASR 将语音转换为文本，再交给 InternS2。ASR 可选 FunASR、SenseVoice 或 Whisper 系列，第一版可先采用录音后上传的非流式方式。

### 10.2 手势

第一版只支持固定手势，例如：

- 上、下、左、右；
- 前、后；
- 停止；
- 急停。

固定手势先由 MediaPipe Hands 或同类关键点模型生成稳定手势事件，再由智能体映射为相对移动任务。指向手势本身不等于三维入点或靶点；若以后需要用手势选择三维点，必须增加相机标定、深度信息和坐标配准模块。

### 10.3 仲裁顺序

```text
急停 > 停止 > 普通语音 > 普通手势
```

规则：

1. 急停和停止不等待 InternS2；
2. 检测到用户正在说话时，普通手势只记录、不执行；
3. 语音与手势在冲突窗口内同时出现时选择语音；
4. 手势必须满足置信度和连续稳定帧数；
5. 同一手势持续保持只能触发一次；
6. 每个会话同一时刻只执行一个运动命令；
7. 过期指令不得在网络恢复后补执行。

## 12. 安全与执行边界

### 12.1 确定性检查

任何机械臂工具调用前都必须检查：

- JSON Schema；
- 坐标是否为有限数值；
- 单位和坐标系；
- 工作空间；
- 单次最大位移；
- 速度和加速度上限；
- 目标是否可达；
- 当前是否存在运动任务；
- 当前是否急停；
- 命令是否过期；
- 是否处于允许的运行模式。

### 12.2 初始配置

```yaml
runtime:
  mode: simulation
  puncture_execution_enabled: false

coordinates:
  default_frame: robot_base
  default_unit: mm
  default_relative_step_mm: 5.0
  tcp: needle_tip

safety:
  max_translation_per_command_mm: 20.0
  max_speed_mm_s: 10.0
  entry_tolerance_mm: 1.0
  stop_on_client_disconnect: true
```

这些数值只是仿真初始配置，后续应根据机械臂型号和老师要求调整，不能直接用于真实设备。

### 12.3 真实机械臂边界

未来接入真实机械臂前至少需要：

- 明确机械臂型号、驱动接口和坐标系；

- 完成仿真回归和离线验证；
- 对学长工具的输出格式和安全属性完成联合测试。

当前代码必须默认 `mode: simulation` 且 `puncture_execution_enabled: false`。

- 机械臂 TCP 轨迹和最终误差；
- 是否到达入点；
- 路径规划工具原始输入输出；
- 仲裁、停止、急停和失败事件；
- 仿真随机种子和必要的视频片段。

## 18. 开发前需要确认的参数

以下内容不阻塞阶段 0，但应在对应阶段开始前确认：

1. 仿真机械臂或简化针架的型号和自由度；
2. “到达入点”使用针尖还是其他 TCP；
3. 仿真世界坐标系和机械臂基座坐标系约定；
4. 入点和靶点默认单位；
5. 到达入点允许的位置误差；
6. “一点”的默认移动距离；
7. 相对方向默认参考坐标系；
8. 仿真机械臂的工作空间和速度上限；
9. 第一版固定手势集合；
10. ASR 方案和主要语言；
11. 学长路径规划工具的调用协议；
12. 路径规划输出的准确字段和控制含义；
13. 路径规划工具使用的坐标系、单位和版本策略；
14. 服务器 GPU、OpenGL/EGL、Docker 和端口情况。

## 19. 最终技术决策

1. NavGPT 及其 DeepSeek 适配全部移除。
2. InternS2 是非结构化数据理解与工具调度中心。
3. InternS2 输出统一 JSON，不直接输出底层机械臂控制量。
4. 完整任务先调用机械臂定位工具，再调用路径规划工具。
5. 机械臂到达入点是调用路径规划工具的前置条件。
6. 学长团队负责穿刺路径规划算法，本项目只负责工具适配和调用。
7. 当前仿真只展示机械臂移动到入点和相对移动。
8. “往上抬一点”等指令不需要入点、靶点或路径规划。
9. 当前仿真不实现针从入点到靶点的穿刺过程。
10. 使用统一 `RobotController` 隔离仿真与未来真实机械臂。
11. 使用 Mock 路径规划工具完成学长工具交付前的联调。
12. 使用 FastAPI + React 在本地浏览器显示远程服务器仿真。
13. 语音经 ASR 转成文本；固定手势转换为受控事件。
14. 指令优先级为“急停 > 停止 > 语音 > 手势”。
15. 当前默认只允许仿真，穿刺执行功能必须关闭。
